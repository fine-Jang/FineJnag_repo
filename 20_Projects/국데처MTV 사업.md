# 국데처MTV 사업 — 구성도 작성 기준

국가데이터처 SGIS 오픈플랫폼의 VMware → OpenShift 전환 및 MTV 이관 사업.
이 문서는 현재 작업 폴더에서 사용자 정정 사항을 기록한 구성 기준이다. 기존 상세 사업 문서는 같은 저장소의 selkie 작업 폴더에 있으며, 아래 최신 확인 사항이 이전 구성 기록보다 우선한다.

## 현재 구성(AS-IS) — 2026-10-09 사용자 정정

| 구분 | 기존 VMware HV | VM 수량(기존 기록) |
|---|---|---|
| 외부망 | **2대** | 13식 |
| 내부망 | **3대** | 26식 |
| 합계 | **5대** | **39식** |

이번 정정은 HV 수량 및 전환 역할에 관한 것이다. VM 수량은 기존 기록을 유지한다.
2026-10-09 사용자 재확인에 따라 외부망 HV 2대·내부망 HV 3대로 정정합니다.

## 기존 HV의 최종 역할(TO-BE)

| 구분 | 기존 HV 활용 |
|---|---|
| 외부망 2대 | HV#01은 MTV 이후 Worker2, HV#02는 먼저 Worker1으로 전환. Bastion 장비 출처 확인 필요 |
| 내부망 3대 | HV#01은 MTV 이후 Worker2. HV#02·HV#03 중 Worker1 대상 선정 및 잔여 장비 용도 확인 필요 |

기존 HV 수량은 외부망 2대·내부망 3대입니다. 외부망 Bastion은 기존 장비 재구성 계획을 유지하되 대상 장비 출처를 확인해야 합니다. 외부 HV#02는 Worker1 전환 대상이며, 내부망은 HV#02·HV#03 중 Worker1 전환 장비와 잔여 장비의 용도를 확인해야 합니다. 각 망 HV#01은 MTV 이후 Worker2로 전환합니다.

| AS-IS 장비 | 재구성·MTV 진행 중 | MTV 이후 |
|---|---|---|
| 외부 HV#01 | VMware 유지 — MTV 이관 원본 | **Worker Node#02** |
| 외부 HV#02 | Worker Node#01 | Worker Node#01 유지 |
| 내부 HV#01 | VMware 유지 — MTV 이관 원본 | **Worker Node#02** |
| 내부 HV#02·HV#03 | Worker1 대상 1대 선정 및 잔여 1대 용도 확인 필요 | 배정 확인 필요 |

## 망별 VMware 호스트 전환 순서

### 최종 TO-BE — 최신 사용자 지정

| 망 | 역할 | 장비 출처·전환 방식 |
|---|---|---|
| 외부망 | Master | 재활용 서버 |
| 외부망 | Bastion | 기존 장비 재구성 |
| 외부망 | Worker2 | HV#01을 MTV 원본으로 유지한 후 노드 전환 |
| 외부망 | Worker1 | 기존 장비 재구성 |
| 내부망 | Master | 재활용 서버 |
| 내부망 | Bastion | 재활용 서버 |
| 내부망 | Worker2 | HV#01을 MTV 원본으로 유지한 후 노드 전환 |
| 내부망 | Worker1 | 기존 장비 재구성 |

최신 지정에 따라 MTV 이후 전환 노드는 **Worker2**, 먼저 재구성하는 노드는 **Worker1**이다. 이전의 반대 번호 표기는 이 기준으로 정정한다.

1. 각 망의 **HV#01**에 해당 망의 VM을 집약하여 VMware 이관 원본으로 유지한다.
2. VM을 비운 Worker 전환 대상 1대를 먼저 OpenShift **Worker Node#01**로 전환한다.
3. MTV로 원본 VMware VM을 OpenShift로 이관한다.
4. MTV 이후 각 망의 원본 VMware **HV#01을 Worker Node#02로 전환**한다. 세부 검증·원복 보관 조건과 전환 일정은 별도 협의한다.

따라서 망별 Worker는 재구성 초기 1대에서 최종 2대로 전환한다. 외부망 Bastion의 장비 출처는 추가 확인하며, 실제 작업 순서·수행일은 별도 확정한다. 위 내용은 계획이며 수행 완료 기록이 아니다.

## 작업 범위 — 2026-10-09 확인

- DB 레거시 풀은 재구성 대상에서 제외하며, 재구성 구성도 및 장비 전환표에 포함하지 않습니다.
- Worker 전환 순서는 제공 이미지 기준으로 확정합니다. **Worker1 선구축 → MTV 이관 → 각 망 HV#01을 Worker2로 전환**합니다.
- 기존 HV 수량은 작업계획서와 기존 사용자 지정에 따라 외부망 2대·내부망 3대로 정정합니다.

## 구성도 표현 기준

- 외부망·내부망별 AS-IS와 최종 TO-BE를 비교한다.
- 이관 중간 구성에는 Worker 1대와 VMware 원본 호스트 1대의 공존을 표시한다.
- AS-IS의 `—`는 현재 해당 장비가 없고 추후 재활용 장비를 투입한다는 의미이다.
- 사용자가 제공한 `ocp418-podonly-topology-v0.5.html`의 VM 풀 표현 형식을 참고한다. 예시의 버전·Bond·브리지 설정을 사업 확정값으로 간주하지 않는다.
- Master의 상세 물리/가상 구성 및 망별 NIC/Bond 설정은 추가 확인한다. 역할별 장비 출처는 아래 최종 TO-BE 표를 따른다.

## 스토리지 및 IP 할당 — 2026-10-08 사용자 확인

- **최신 확인: 기존 VMware 데이터스토어 유형은 VMFS이며, EMC → FC(광채널) 연결 → LUN 할당 → VMFS 구성입니다.**
- OpenShift 구축 후 **동일 EMC 스토리지에 대한 CSI 드라이버를 설치하고 CSI를 통해 MTV 대상 볼륨을 할당**할 예정입니다.
- CSI는 볼륨 할당·연동 방식이며, 대상의 실제 데이터 연결 프로토콜은 EMC 모델 및 드라이버 지원 범위 확인 후 확정합니다.
- 이관 및 원본 보관 기간에는 **기존 VMware 데이터스토어 유지분 + MTV 대상 볼륨**을 동시에 확보해야 합니다. 원본과 대상 공간은 별도로 관리합니다.
- 앞서 전달된 NFS의 NAS·백업 등 적용 범위는 별도 확인하며, VMware 데이터스토어 연결 방식으로 적용하지 않습니다.
- 기존 하이퍼바이저의 **서비스망·NAS/BK망·관리망 IP는 그대로 재사용**할 예정이다.
- IP 재사용의 적용 대상은 사용자가 명시한 하이퍼바이저 네트워크이다. 개별 VM IP 유지 여부를 이 확인만으로 확정하지 않는다.

| 망 구분 | 신규 인프라 서버 역할 | IP 할당 |
|---|---|---|
| 외부망 | Master Node | **신규 할당 필요** |
| 내부망 | Bastion | **신규 할당 필요** |
| 내부망 | Master Node | **신규 할당 필요** |

위 표는 신규 IP 할당 대상 역할을 나타낸다. 실제 IP·서브넷·VLAN, 역할별 연결망과 인터페이스 수, Master 상세 구성은 별도 확인한다. API·Ingress VIP 및 BMC IP는 이 표에 포함해 확정한 것이 아니다.

EMC 모델·펌웨어, 기존 FC LUN·데이터스토어 매핑, CSI 지원 버전·연결 방식·StorageClass·볼륨 모드와 망별 풀·가용 용량은 추가 확인합니다.

### 동일 EMC 스토리지 용량 계획

- 사업 관련 동시 확보 공간 = 기존 VMware 데이터스토어 유지분 + MTV 대상 볼륨 + 추가 공간·운영 여유입니다.
- 추가 필요 공간 = MTV 대상 볼륨 + 오버헤드·플랫폼 공간 + 임시·스냅샷 공간 + 운영 여유입니다.
- 부족분 = max(0, 추가 필요 공간 − 사업에 할당 가능한 실제 잔여 용량)입니다.
- 실제 잔여 용량은 원본 데이터스토어 유지분을 제외한 값이며, 원본 사용량을 추가 필요 공간에 중복 가산하지 않습니다. 원본 삭제로 회수할 공간도 사전 가용 용량에 포함하지 않습니다.
- 동일 EMC 사용이 동일 풀 사용을 의미하지는 않습니다. 망별 풀을 확인하고 같은 풀의 잔여 용량은 중복 계산하지 않습니다.
- HV#01의 Worker2 전환과 원본 LUN·데이터스토어 회수는 별도 판단 항목입니다. 원본 공간은 보관·원복 기준 충족 후 회수합니다.

## 2026-10-12 일괄 반영 사항

- OCP 설치는 폐쇄망 UPI 방식으로 확정합니다. Bastion에서 설치 도구·Ignition을 준비하고 별도 Bootstrap 및 내부 미러 레지스트리를 구성합니다.
- IP 상세정보는 국데터 SGIS 구성을 참조합니다. V2의 별도 IP 기입표는 삭제합니다.
- V2 구성도는 Worker1 → Worker2 순으로 표시하며, MTV 이후 HV#01에서 전환하는 Worker2를 강조합니다.
- 문서 색상은 청회색·네이비 중심이며, Worker2는 주황색으로 강조합니다.
