01. 작업 개요

국가데이터처 SGIS 오픈플랫폼의 VMware 가상머신을 OpenShift Virtualization으로 이관하는 작업. 망별 Bastion·Master KVM 서버 구축 후 OpenShift 클러스터 설치, 비어 있는 하이퍼바이저의 Worker1 전환, Migration Toolkit for Virtualization(MTV)을 이용한 VM 이관 순서로 진행. 이관과 업무 확인 완료 후 잔여 원본 하이퍼바이저를 Worker2로 전환.

구축 단계(①~⑤)는 외부망(인터넷망)·내부망(업무망) 함께 진행, MTV 이관(⑥)은 외부망 먼저 진행 후 내부망 적용. 적용 버전은 OCP 4.22(RHCOS), Bastion·KVM 서버 RHEL 9.8, MTV 2.12.

주의할 점
  • Worker 전환은 원복 불가. 하이퍼바이저에 OpenShift 노드 OS(RHCOS)를 설치하면 ESXi와 기존 설정 삭제. 전환 전 확인 항목을 모두 충족한 경우에만 진행.
  • Worker2 전환 이후 원본 VM으로 복귀 불가. 원본 하이퍼바이저 전환 시 VMware 환경과 vCenter가 함께 사라짐. 모든 VM의 이관 후 확인과 업무 담당의 원본 불필요 확인 완료 후 진행.
  • 원본 VM은 끈 상태로 보존. 이관이 끝난 원본 VM은 Worker2 전환 전까지 삭제하지 않고, 문제 발생 시 원본 VM 재기동으로 서비스 복구.
  • DNS VM은 모든 VM 이관 완료까지 유지. MTV가 vCenter·ESXi에 이름으로 접속하므로, DNS VM을 먼저 끄면 이관 중단 가능.

03. VM 이관

Cold 방식 이관. 원본 VM 종료 후 디스크를 네트워크(VDDK)로 복사하여 OpenShift VM으로 변환. VM마다 이관 시간 동안 서비스 중단, VM 1대씩 이관. 망마다 vCenter가 별도이므로 이관 연결(Provider)도 망별 구성.

이관 전 VM 점검

점검 항목확인 내용
OS · 부팅OS 종류·버전(RHEL 8.9, Windows Server 2022), BIOS/EFI, Secure Boot 사용 여부
네트워크 · IP어댑터별 포트그룹(서비스 130, nasbak 701·710)과 IP/prefix, 게이트웨이, DNS, 정적 경로 기록
디스크디스크 개수·크기, 공유 디스크·RDM·vTPM·암호화 여부, 게스트 안 NFS·iSCSI 직접 마운트 여부
스냅샷이관 전 스냅샷 정리, 이관 시작 후 스냅샷 생성 금지
WindowsFast Startup 해제, 동적 디스크 여부, DHCP Client 서비스 상태
에이전트백신 등 에이전트 설치 여부

이관 절차

순서작업
1. 연결 구성vSphere 연결(Provider) 생성, 인벤토리의 VM 표시 확인
2. 매핑원본 포트그룹을 대상 네트워크에 연결(서비스 130 → 서비스망, nasbak 701·710 → 백업망), 원본 데이터스토어를 대상 스토리지에 연결
3. 이관 계획VM 1대 단위로 이관 계획 생성, 사전 검증 결과의 경고 여부 확인
4. 원본 종료게스트 안에서 원본 VM 정상 종료(VMware Tools 미설치로 직접 종료)
5. 이관 실행이관 실행 및 진행 상태 확인. 대상 VM은 꺼진 상태로 생성하여 원본과 동시 기동 방지
6. 확인 후 기동대상 VM 기동 후 아래 이관 후 확인 수행

이관 후 확인

  • Worker 노드에서 VM 정상 기동
  • 서비스망 IP·MAC이 이관 전과 동일(IP 미적용 시 사전 기록 값으로 게스트 안에서 설정)
  • 기본 경로 중복 없음
  • 게스트 에이전트 동작
  • 업무 담당의 서비스 동작 확인
  • 원본 VM은 전원을 끈 상태로 보존
