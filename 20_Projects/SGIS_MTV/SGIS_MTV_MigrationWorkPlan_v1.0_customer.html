01. 작업 개요

본 작업은 국가데이터처 SGIS 오픈플랫폼의 VMware 가상머신을 OpenShift Virtualization으로 이관하는 작업입니다. 망별로 Bastion과 Master KVM 서버를 구축하여 OpenShift 클러스터를 설치하고, 비어 있는 하이퍼바이저를 Worker1로 전환한 뒤 Migration Toolkit for Virtualization(MTV)으로 VM을 이관합니다. 이관과 업무 확인이 끝나면 원본 하이퍼바이저를 Worker2로 전환합니다.

외부망을 먼저 수행하고, 외부망에서 검증한 절차와 소요 시간을 내부망에 적용합니다.

OpenShift 클러스터2개외부망 1 / 내부망 1 · 망별 독립
이관 대상 VM35대외부망 11 / 내부망 24 · vCenter·DNS 제외
적용 버전OCP 4.22RHCOS · Bastion RHEL 9.8 · MTV 2.12

주의할 점
  • Worker 전환은 원복이 불가합니다. 하이퍼바이저에 OpenShift 노드 OS(RHCOS)를 설치하면 ESXi와 기존 설정이 삭제됩니다. 전환 전 확인 항목을 모두 충족한 경우에만 진행합니다.
  • Worker2 전환 이후에는 원본 VM으로 복귀할 수 없습니다. 원본 하이퍼바이저를 전환하면 VMware 환경과 vCenter가 함께 사라집니다. 모든 VM의 이관 후 확인과 업무 담당의 원본 불필요 확인이 끝난 뒤에 진행합니다.
  • 원본 VM은 끈 상태로 보존합니다. 이관이 끝난 원본 VM은 Worker2 전환 전까지 삭제하지 않으며, 문제가 생기면 원본 VM을 다시 기동하여 서비스를 복구합니다.
  • DNS VM은 모든 VM 이관이 끝날 때까지 유지합니다. MTV는 vCenter·ESXi에 이름으로 접속하므로, DNS VM을 먼저 끄면 이관이 중단될 수 있습니다.

02. 단계별 작업 내용

단계작업 내용완료 기준협조
① Bastion 구축재활용 TNS-2100에 RHEL 9.8을 설치하고 관리망(2포트)과 백업망(nas, 2포트)을 구성합니다. DNS, 로드밸런서, 시간 동기화(NTP), 설치 파일 배포용 HTTP 서버, 미러 레지스트리를 구축하고 반입한 설치 이미지와 VDDK 이미지를 적재합니다. vCenter·ESXi 이름도 Bastion DNS에 등록합니다.DNS 정·역방향 조회 정상, 미러 레지스트리 접속 정상, 로드밸런서 기동NTP 장비 정보, 방화벽 정책
② 클러스터 설치Master KVM 서버에 RHEL 9.8과 KVM을 구성하고 Master VM 3대와 설치용 임시 VM(bootstrap)을 만듭니다. 폐쇄망 UPI 방식으로 OpenShift를 설치하며, Master에는 업무 VM이 올라가지 않도록 설치 전에 설정합니다. 설치 후 임시 VM은 삭제합니다.Master 3대 Ready, 미러 이미지 설정 적용—
③ Worker1 전환DNS VM을 원본 하이퍼바이저로 옮겨 대상 하이퍼바이저를 비웁니다. 설정을 백업하고 vCenter에서 제거한 뒤 LUN 매핑을 해제합니다. 노드 네트워크(관리·백업·서비스 bond)를 구성하고 OpenShift 노드로 설치하여 클러스터에 편입합니다. 기존 하이퍼바이저 IP를 재사용합니다.Worker1 Ready, bond 이중화 시험 완료, 스토리지 경로 이중화 확인, 설치 완료VMware · 스토리지 · 네트워크
④ 클러스터 구성OpenShift Virtualization, MTV, NMState를 설치합니다. VM이 연결될 서비스망(VLAN 130)·백업망 브리지와 네트워크 정의를 만들고, 스토리지 엔지니어가 구성한 StorageClass를 확인합니다. 업데이트 서비스(OSUS)를 구성합니다.Operator 정상, 네트워크 정의 생성, 테스트 볼륨 할당 정상스토리지(CSI·StorageClass)
⑤ VM 이관VM별 점검 후 MTV로 VM을 1대씩 이관합니다. 첫 이관은 1대로 수행하여 결과를 확인한 뒤 나머지를 진행합니다. 03장의 절차를 따릅니다.VM 기동, IP·MAC 유지, 업무 확인VMware(계정), 업무 담당
⑥ Worker2 전환전환 전 확인 후 원본 하이퍼바이저를 vCenter에서 제거하고 Worker2로 전환합니다. Worker 2대 간 Live Migration을 시험하고 etcd 일일 백업을 설정합니다.Worker2 Ready, Live Migration 성공, 첫 백업 생성VMware · 스토리지 · 업무 담당

내부망은 HV#03을 Master KVM 서버로, 비어 있는 HV#01을 Worker1로, 업무 VM이 있는 HV#02를 Worker2로 전환하는 점만 다르며 같은 순서로 진행합니다. 내부망 HV#03의 DNS VM은 Master 구성 전에 HV#02로 옮깁니다.

03. VM 이관

이관은 Cold 방식으로, 원본 VM을 종료한 뒤 디스크를 네트워크(VDDK)로 복사하여 OpenShift VM으로 변환합니다. VM마다 이관 시간 동안 서비스가 중단되며 VM은 1대씩 이관합니다. 망마다 vCenter가 따로 있어 이관 연결(Provider)도 망별로 구성합니다.

이관 전 VM 점검

점검 항목확인 내용
OS · 부팅OS 종류·버전(RHEL 8.9, Windows Server 2022), BIOS/EFI, Secure Boot 사용 여부
네트워크 · IP어댑터별 포트그룹(서비스 130, nasbak 701·710)과 IP/prefix, 게이트웨이, DNS, 정적 경로 기록
디스크디스크 개수·크기, 공유 디스크·RDM·vTPM·암호화 여부, 게스트 안 NFS·iSCSI 직접 마운트 여부
스냅샷이관 전 스냅샷 정리. 이관 시작 후에는 스냅샷을 만들지 않습니다.
WindowsFast Startup 해제, 동적 디스크 여부, DHCP Client 서비스 상태
에이전트백신 등 에이전트 설치 여부

이관 절차

순서작업
1. 연결 구성vSphere 연결(Provider)을 만들고 인벤토리에 VM이 보이는지 확인합니다.
2. 매핑원본 포트그룹을 대상 네트워크에 연결합니다(서비스 130 → 서비스망, nasbak 701·710 → 백업망). 원본 데이터스토어를 대상 스토리지에 연결합니다.
3. 이관 계획VM 1대 단위로 이관 계획을 만들고 사전 검증 결과에 경고가 없는지 확인합니다.
4. 원본 종료게스트 안에서 원본 VM을 정상 종료합니다(VMware Tools를 설치하지 않으므로 직접 종료).
5. 이관 실행이관을 실행하고 진행 상태를 확인합니다. 대상 VM은 꺼진 상태로 만들어 원본과 동시에 켜지지 않게 합니다.
6. 확인 후 기동대상 VM을 기동하여 아래 이관 후 확인을 수행합니다.

이관 후 확인

  • VM이 Worker 노드에서 정상 기동합니다.
  • 서비스망 IP와 MAC이 이관 전과 같습니다. IP가 적용되지 않으면 사전 기록 값으로 게스트 안에서 설정합니다.
  • 기본 경로가 중복되지 않았습니다.
  • 게스트 에이전트가 동작합니다.
  • 업무 담당이 서비스 동작을 확인했습니다.
  • 원본 VM은 전원을 끈 상태로 보존합니다.

05. 주요 위험 및 대응

위험내용대응
서비스 중단Cold 이관이므로 VM마다 이관 시간 동안 서비스가 중단됩니다.첫 VM으로 소요 시간을 측정하여 VM별 작업 시간을 정하고 업무 담당과 일정을 협의합니다.
IP 유지VMware Tools를 설치하지 않으므로 IP 자동 유지 기능이 동작하지 않을 수 있습니다.VM별 IP를 사전에 기록하고, 이관 후 게스트 안에서 확인·설정합니다.
원복 불가 단계Worker 전환은 원복이 불가하며, Worker2 전환 후에는 원본으로 복귀할 수 없습니다.단계 진입 조건(02장)을 모두 충족한 경우에만 진행하고, 원본 VM은 Worker2 전환 전까지 보존합니다.
스토리지 경로FC 경로가 이중화되지 않으면 경로 장애 시 VM 디스크 접근이 끊깁니다.Worker 편입 후 경로 수와 상태를 스토리지 엔지니어와 확인하고, 이중화가 확인되지 않으면 이관을 시작하지 않습니다.
