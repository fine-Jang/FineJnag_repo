01. 추진 개요

본 작업은 기존 VMware 환경의 가상머신을 OpenShift로 이관하고, 기존 장비와 재활용 서버를 활용하여 대상 인프라를 구성하는 것을 목적으로 합니다. 망별 HV#01은 VM 집약 및 MTV 이관 원본으로 유지합니다. Bastion과 Master(KVM 호스트의 VM 3식)를 구축한 뒤 Worker1을 편입하고, 이관 완료 후 HV#01을 Worker2로 전환합니다.

이관 대상 VM39식외부망 13 / 내부망 26 · DB 제외
재활용 TNS-2100 투입3대외부 Master·Bastion / 내부 Bastion · 2대 여유분
스토리지동일 EMC원본 VMFS 유지 + CSI 대상 볼륨

VM 수량과 재활용 장비 수량은 기존 사업 기록 기준입니다. 호스트별 VM 배치 및 수행 시점의 실제 자원 현황은 착수 전 대조합니다.

동일 EMC 스토리지 사용 계획 — 이관 기간

CSI는 볼륨 할당·연동 방식입니다. FC 등 실제 데이터 연결 프로토콜은 EMC 모델과 지원 드라이버를 확인한 후 확정합니다. NAS/BK망과 VM 데이터스토어의 FC 경로는 구분합니다. 기존 NFS 언급은 NAS·백업 용도 등 적용 범위를 별도로 확인하며, VM 데이터스토어 방식으로 표기하지 않습니다.

스토리지 용량 산정 초안

동일 EMC에서 기존 VMware VMFS 데이터스토어를 유지하면서 MTV 대상 볼륨을 추가 확보합니다. 원본 데이터스토어와 대상 볼륨을 별도로 관리하며, 이관 및 원본 보관 기간에는 두 영역을 동시에 수용해야 합니다. 풀별 잔여 용량과 망별 VM 설정·사용 용량을 확보한 뒤 산정합니다.

사업 관련 동시 확보 공간 = 기존 VMware VMFS 데이터스토어 유지분 + MTV 대상 볼륨 + 추가 공간·운영 여유
추가 필요 공간 = MTV 대상 볼륨 + 오버헤드·플랫폼 공간 + 임시·스냅샷 공간 + 운영 여유
부족분 = max(0, 추가 필요 공간 − 사업에 할당 가능한 실제 잔여 용량)

산정식은 초기 검토 기준이며, 실제 필요 용량은 자원 현황 확보 후 확정합니다. 사업에 할당 가능한 실제 잔여 용량은 원본 데이터스토어 유지분을 제외한 값입니다. 원본 유지분은 추가 필요 공간에 중복 가산하지 않으며, 원본 삭제로 회수할 용량도 사전에 가용 공간으로 계산하지 않습니다. 같은 풀을 공유하는 경우 여유 공간을 망별로 중복 계산하지 않습니다.

설치는 Bastion → Master KVM 호스트 → Bootstrap·Master VM → Worker1 순서로만 진행할 수 있습니다. 3단계에서는 장비를 비우고 LUN 매핑만 해제하며, OS 설치는 4단계 이후 순서대로 진행합니다. 작업 명령, 수행일 및 소요 시간은 상세 작업 절차서에 반영합니다.

폐쇄망 UPI 설치 절차

단계작업 내용
1. 사전 준비Bastion에 설치 도구와 CLI를 준비하고 DNS·NTP·API/Ingress 로드밸런서 및 네트워크를 구성합니다. Master KVM 호스트에 RHEL 9.8·KVM·브리지를 구성합니다.
2. 폐쇄망 미러 구성필요한 OCP·가상화·MTV·CSI·VDDK 이미지를 Bastion의 미러 레지스트리에 망별로 반입하고 인증서·인증·미러 설정을 준비합니다.
3. 설치 설정 생성클러스터 구성과 미러 정보를 반영하여 설치 설정 및 Bootstrap·Master·Worker용 Ignition 파일을 생성합니다.
4. Bootstrap 및 노드 설치Master KVM 호스트에 Bootstrap 임시 VM과 Master VM 3식을 생성하여 RHCOS와 해당 Ignition을 적용합니다. 이어서 Worker1(HV#02)에 RHCOS를 설치합니다. 각 망 HV#01은 MTV 원본으로 유지하며 최초 설치 대상에서 제외합니다.
5. Bootstrap 완료 확인Bootstrap 완료를 확인한 뒤 로드밸런서에서 Bootstrap 대상을 제거하고 Bootstrap VM을 삭제합니다.
6. 클러스터 완료 검증노드·CSR·ClusterOperator 상태와 API·콘솔·미러 접근을 확인합니다. 이후 가상화·EMC CSI·MTV를 구성합니다.
7. MTV 이후 Worker2 편입원본 보관·원복 조건을 확인한 뒤 HV#01에 신규 노드용 설정을 적용하고 Worker2로 편입합니다.

설치 방식은 UPI(platform: none)로 확정합니다. Master는 KVM VM 3식, Bootstrap은 같은 KVM 호스트의 임시 VM입니다. 재설치 전 EMC에서 VMFS LUN 매핑을 해제하고 설치 디스크는 by-id로 지정하여 원본 데이터를 보존합니다. RHCOS 멀티패스 설정은 MachineConfig로 적용합니다.

원복 판단 기준, 결정 시점, 원본 보관 기간, 데이터 복구 방법 및 최종 검수 조건은 협의 후 확정합니다. Worker2 전환은 이관 완료 후 최소 1주 무장애, 원복 요청 없음, 백업 복구 시험 통과, 업무 담당 확인을 모두 충족한 경우에 진행합니다. HV#01의 Worker2 전환과 원본 LUN·데이터스토어 회수는 별도 판단 항목이며, 원본 공간은 보관·원복 기준 충족 후 회수합니다.
