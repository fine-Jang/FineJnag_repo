# 국데처 MTV 작업계획서 v2.8 수정안

V2.7 작업계획서를 기준으로 VDDK를 사용 확정 시 조건부 이관 방식으로 추가한 릴리스 기록입니다. 반영본은 [SGIS_MTV_WorkPlan_v2.8.html](SGIS_MTV_WorkPlan_v2.8.html)입니다. 아래 항목 외의 내용은 v2.7과 같습니다.

## 결정

- 이관 방식 1순위는 Storage Copy Offload를 유지합니다.
- VDDK는 라이선스 이슈로 이관 방식 검토 중이며, **사용 확정 시에만** ② 방식으로 적용합니다.
- 선택 순서: ① Copy Offload(스토리지가 PowerMax + CSI 지원) → ② VDDK(사용 확정 시) → ③ Skip VDDK cold(대안).

## v2.8 반영 사항

1. **"VDDK 불가" 확정 문구 정정**
   - 01장 이관 방식: `VDDK 사용 불가` → `이관 방식 검토 중(VDDK 라이선스 이슈)`, 방식 나열에 VDDK(사용 확정 시) 추가.
   - 04장 이관 방식 표 Copy Offload 행: `warm은 이 방식으로만 가능` → `warm 가능. VDDK 미사용 시 warm은 이 방식으로만 가능`.
   - 05장 UPI 미러 구성: `(VDDK 사용 불가로 제외)` → `(VDDK 이미지는 사용 확정 시 추가)`.
   - 05장 서비스 전환 순서 웜 이관 행: `Copy Offload만` → `Copy Offload · VDDK`, 두 방식 모두 불가하면 cold만 가능.
   - 06장 위험: `VDDK 사용 불가` → `VDDK 사용 여부 미확정`(Copy Offload·VDDK 모두 불가 시 일정 위험), 대응에 VDDK 사용 가능 여부 조기 재확인 추가.

2. **방식 나열 확장**
   - 04장 스토리지 매핑 그림: 가운데 열에 `② VDDK (사용 확정 시)` 점선 상자 추가, 기존 ②는 ③ Skip VDDK cold로 변경, `①·② 혼용 불가` → `한 plan에는 한 방식`. 그림 높이 380 → 450.
   - 04장 이관 방식 표: ② VDDK 행 추가(조건: VDDK 파일 확보·이미지 빌드·Bastion 미러 반입·Provider 지정 / 특징: ESXi 경유 네트워크 복사, CBT로 warm 가능, 라이선스 이슈로 사용 확정 전까지 적용하지 않음), Skip VDDK cold는 ③으로 변경.
   - 04장 전송 시간 설명, 05장 9단계·콜드 이관 행, 06장 스토리지 모델·CSI 위험 대안, 07장 12월 일정: 세 방식으로 나열.

3. **신규 항목**
   - 05장 1단계 미러 반입 목록에 `VDDK는 사용 확정 시` 추가.
   - 07장 확정 항목 VMware 엔지니어에 `VDDK 라이선스·다운로드 가능 여부(Broadcom 지원 계약)` 추가.

4. **이관 직후 OS TAR 백업 수동 실행 추가**
   - 확인된 백업 방식: 데이터 영역(/DATA 등)은 게스트 에이전트 백업, OS 영역은 쉘 스크립트 TAR 백업(서버에서 추출 후 외부로 별도 소산), Windows VM은 전용 백업툴. 모두 VM 내부 동작이므로 이관 후에도 유지되며 Worker의 서비스망·nasbak망 IP는 불필요합니다. fstab은 UUID 사용으로 장치 이름 변경 영향 없음.
   - 05장 10단계 회차별 본 이관 흐름 끝에 `OS TAR 백업 수동 실행(이관 후 기준 백업)` 추가.
   - VM별 이관 완료 점검표에 `OS 기준 백업` 행 추가: 이관 직후 TAR 백업 스크립트를 수동 실행해 정상 완료·백업 파일 생성을 확인하고, 이관 전 백업에는 virtio 드라이버가 없으므로 이 백업을 이관 후 OS 복구 기준점으로 사용.

5. **검증**
   - 변경 21건 각 1회 적용 확인, 문서 내 `VDDK 사용 불가`·`실사 시 사용 불가` 확정 표현 없음(VDDK는 `라이선스 이슈`로 표기).
   - 구성도 SVG 글자 넘침 검사 결과 넘침 없음.

6. **버전·수정일**
   - 표지 `VERSION 2.8`, 수정일 2026.10.13.
