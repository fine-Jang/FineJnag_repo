01. 추진 개요

본 작업은 기존 VMware 환경의 가상머신을 OpenShift로 이관하고, 기존 장비와 재활용 서버를 활용하여 대상 인프라를 구성하는 것을 목적으로 합니다. 실사 결과 업무 VM은 외부망 HV#01, 내부망 HV#02에 이미 모여 있어 별도의 VM 집약 단계 없이 이 HV를 MTV 원본으로 유지합니다. 외부 HV#02·내부 HV#03의 DNS 설정과 레코드를 각 망의 Bastion DNS로 이관하고 질의를 검증한 뒤 원본 DNS VM을 종료합니다. 외부 HV#02와 내부 HV#01은 Worker1, 내부 HV#03은 Master KVM 호스트로 재구성하고, Master VM 3식은 외부 TNS-2100과 내부 HV#03에 구성합니다. Bastion과 DNS는 외부·내부 재활용 TNS-2100에 각각 구축합니다. 이관·업무 검증·안정화 완료 후 원본 HV를 Worker2로 전환합니다.

목표 구성은 MTV 완료 후를 기준으로 작성했습니다. 업무 VM이 모여 있는 외부 HV#01·내부 HV#02는 MTV 원본으로 유지하고, 이관·업무 검증·안정화와 원복 판단이 끝난 뒤 Worker2로 전환합니다. 그 기간에는 Worker1만으로 운영합니다. vCenter VM은 MTV가 인벤토리를 읽으므로 마지막 이관까지 유지합니다. 외부 Master는 재활용 TNS-2100, 내부 Master는 기존 HV#03 재구성 호스트에 Master VM 3식을 구성합니다. etcd 정족수는 VM 3식으로 확보하되 KVM 호스트는 물리 단일 장애점이므로 06장의 위험 대응을 적용합니다.

DB 레거시 풀은 재구성 대상에서 제외합니다. 연결선은 논리적 네트워크 구성을 나타내며 포트·bond·브리지·FC 상세는 04장 전체 구성도에 표시합니다. 기존 DNS VM은 MTV 대상에서 제외합니다. 외부·내부 Bastion에 DNS를 각각 구축하고 기존 설정과 레코드를 이관합니다. 질의와 vCenter·ESXi 관리 연결을 확인한 뒤 원본 VM을 종료·보관하고, 외부 HV#02·내부 HV#03을 재구성합니다. vCLS는 vCenter가 관리하는 시스템 VM으로 이관 대상이 아닙니다.

04. 네트워크·IP 및 스토리지 계획

실사 기준 네트워크·스토리지 구성 (2026-10-12)
기존 HV는 vswitch 3개(서비스, nasbak, 관리·vMotion)에 각각 물리 포트 2개가 연결된 6포트 구성입니다. 관리망은 태그 없음, 서비스망 VLAN 130, nasbak망 VLAN 701·710이며 외부망·내부망이 같습니다. 업무 VM의 VMFS6 데이터스토어는 FC로 연결된 Dell EMC 스토리지(장치 모델 SYMMETRIX)의 LUN이고 모든 HV에 연결되어 있습니다. Worker로 전환하는 HV는 같은 물리 포트·HBA를 그대로 사용합니다.

스토리지 연결 준비

  • 내부 Master HV#03: 재구성 전에 VMFS LUN 매핑을 해제하고, Master KVM 호스트는 etcd·VM 디스크용 로컬 SSD/NVMe를 사용합니다.
  • 재활용 TNS-2100(외부 Master·외부/내부 Bastion): FC에 연결하지 않습니다. etcd는 Master KVM 호스트의 로컬 SSD/NVMe를 사용합니다(외부 TNS-2100·내부 HV#03).

동일 EMC 스토리지 사용 계획 — 이관 기간

스토리지 용량 산정

동일 EMC에서 기존 VMFS 데이터스토어를 유지하면서 MTV 대상 볼륨을 추가로 확보합니다. 원본 사용량은 74.7TB(외부 12.4 + 내부 62.3)이며 이관·원본 보관 기간에는 대상 볼륨이 동시에 필요하므로 약 74.7TB 이상의 추가 공간이 필요합니다. 기존 데이터스토어의 여유 공간은 거의 없으므로(외부 600GB 이상, 내부 200GB 이상) 스토리지 풀의 여유로 확보해야 합니다.

추가 필요 공간 = MTV 대상 볼륨(약 74.7TB) + 파일시스템·플랫폼 오버헤드 + 임시·스냅샷 공간 + 운영 여유
부족분 = max(0, 추가 필요 공간 − 사업에 할당 가능한 스토리지 잔여 용량)

사용량에 스냅샷·ISO 등이 포함되는지는 확인되지 않았습니다. 대상 PVC가 디스크 할당 크기만큼 잡히는지 실제 사용량만큼 잡히는지는 시험 이관에서 확인합니다. VMware 스냅샷은 데이터스토어를 더 채우므로 롤백 수단으로 쓰지 않습니다. 원본 삭제로 회수할 용량은 사전에 가용 공간으로 계산하지 않습니다.

게스트 도구·에이전트VMware Tools, QEMU Guest Agent, 보안·백업·모니터링 에이전트 현황을 기록합니다.변환 후 도구 처리 결과와 대상 에이전트 설치·동작을 확인합니다. VMware Tools 사전 제거를 일괄 지시하지 않습니다(virt-v2v가 이관 중 제거). Tools 미설치 VM은 정상 종료·vNIC 정보 보고를 위해 이관 전에 설치합니다.
스냅샷·웜 이관 조건기존 스냅샷, CBT 상태 및 필요한 여유 공간을 확인합니다. Windows 웜 이관은 VSS 등 사전 조건을 확인합니다. Copy Offload는 스냅샷이 남아 있으면 소프트웨어 복사로 후퇴하므로 이관 전 삭제합니다.사전 복사와 최종 변경분 반영이 정상 완료되는지 확인합니다.
라이선스·시간·서비스하드웨어 정보 종속 라이선스, DNS·시간 동기화, 서비스 자동 기동·배치와 외부 연계를 조사합니다.재인증·재등록 필요 여부와 실제 업무 동작을 확인합니다.
Worker1·EMC 수용 능력망별 Worker1 단독 운영 기간의 CPU·메모리와 원본·대상 스토리지 동시 사용량을 확인합니다.이관 복사와 운영 I/O가 겹치는 조건에서 응답시간·디스크 지연을 확인하고 회차·동시 이관 수를 결정합니다.

시험 대상은 주요 OS, 다중 NIC, 다중 디스크 및 보안·암호화 등 특수 구성을 포함하여 선정합니다. 보정 소요 시간과 허용 기준은 시험 결과를 근거로 회차별 작업계획에 반영합니다.

12/1 ~ 12/11 (잠정)외부망 → 내부망 순서로 서비스 그룹별 본 이관. VM 개수가 아니라 디스크 사용량·서비스 의존성·허용 중단 시간을 기준으로 회차를 편성합니다. 동시 10대 이하는 초기 상한으로 두고 시험 결과에 따라 조정합니다.11월 시험 이관에서 Copy Offload / Skip VDDK별 실효 속도와 사전 검사·전송·기동·업무 검증 시간을 측정하고, 서비스별 작업창과 재시도 여유를 반영해 12월 일정을 재산정합니다.
12/14 ~ 12/23 (잠정)안정화: 업무 모니터링, 백업 정상 확인, 원본 VM 전원 종료 보관실제 이관 종료 후 최소 1주 무장애, 원복 불필요 판단
12/24 ~ 12/30 (조건부)원본 HV → Worker2 편입 (외부 HV#01 · 내부 HV#02)이관·검증·안정화 조건 충족 후 진행. 지연 시 안정화 기간을 줄이지 않고 2027년 1월 이후로 이연합니다.
12/31 (목표)최종 검증·결과서실측 기반 일정 및 선행 작업 결과에 따라 조정

스토리지 표의 시간은 연속 데이터 전송만 계산한 값입니다. 서비스별 순차 처리, 업무 중단 가능 시간, 기동·검증, 작업자 대기 및 실패 후 재시도를 포함하지 않으므로 전체 이관 일정으로 직접 사용하지 않습니다. 실제 여유 기간은 11월 시험 이관에서 측정한 회차별 전체 작업시간을 합산해 확보합니다. 12/25 휴일과 연말 작업 가능일도 반영하며, 일정이 밀리면 Worker2 전환을 이연하고 안정화·원복 확인 기간은 유지합니다. 원본 LUN·데이터스토어 회수는 Worker2 전환과 별도로 판단합니다.

실행 전 확정 항목

  • 스토리지 엔지니어: 스토리지 모델(PowerMax 여부)·펌웨어, PowerMax CSI의 OCP 4.22 지원, RWX Block·스냅샷 지원, 약 74.7TB 추가 용량, Worker 호스트 등록·마스킹, Copy Offload용 관리 계정·Symmetrix ID·포트 그룹
  • VMware 엔지니어: vSphere 정확한 버전(SDDC Manager 사용 여부), 호스트 제거 방법, MTV용 vSphere 역할·계정 권한, ESXi SSH·VIB 허용
  • 네트워크 담당: 포트 속도, 스위치 trunk 허용 VLAN(130·701·710)과 대기 포트 설정, 관리망·서비스망·nasbak망 대역·게이트웨이
  • 작업 담당·고객사: VLAN 701 사용 VM과 11월 중단 일정, 무중단(warm) 필요 VM과 다운타임 창, VMware Tools 미설치 VM 목록, 게스트 OS 버전(Windows Server 2012 R2 등 구형)
  • Master 호스트(외부 TNS-2100·내부 HV#03)의 Master VM 3식 + Bootstrap 수용 사양(약 28~32 vCPU, 112~128GB, SSD/NVMe), etcd 디스크, 외부 Master의 NAS/BK 추가 포설·Bond 및 백업스토리지 연결, 관리 포트·IPMI 연결
  • 외부·내부 Bastion(TNS-2100)의 미러 레지스트리 형태(mirror registry for Red Hat OpenShift 또는 Red Hat Quay)와 PowerMax CSI 이미지 반입 방법, 디스크 용량(약 358GB 이상, 1TB 권장)
  • KVM 호스트·Bastion RHEL 구독 및 OVE 구독 범위
  • DNS VM이 HV·vCenter 외 업무 서비스에서 사용되지 않는지 확인, Bastion DNS 설정·레코드 이관, 이름 조회·관리 연결 검증 및 원본 DNS VM 종료 기준
  • OCP·RHCOS·가상화 기능·MTV·스토리지의 지원 조합 및 실제 하드웨어 호환성
  • 시험 대상·회차별 VM, 이관 방식, 검증·원복·원본 보관 및 완료 기준

본 검토본의 관리 범위는 장비 구성, 네트워크, 스토리지 및 이관 절차입니다.

기술 검토 참고: MTV 2.12 발표(OCP 4.22 대응), Red Hat MTV 문서, Dell CSM Operator 카탈로그. 사업 적용 버전은 구축 전 확정합니다.
