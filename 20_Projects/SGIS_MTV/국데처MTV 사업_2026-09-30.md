# 국데처MTV 사업

## 사업 개요

- **사업명:** 국가데이터처 SGIS 오픈플랫폼 인프라 전환 및 MTV 사업
- **목표:** 기존 VMware 환경을 Red Hat OpenShift(OVE) 환경으로 재구성하고 MTV를 활용해 VM을 이관한다.
- **현재 단계:** 작업 관련 협의 및 기존 인프라 현황 파악
- **OCP 노드 OS 기준:** **OCP 4.22 → RHCOS(RHEL 9.8 기반)**. Master·Worker 장비 호환성은 이 기준으로 확인한다.
- **본 작업 착수 예정:** 2026년 **11월** — 행정작업·장비 재배치 및 10월 전기 포설 등 사전 준비 후 착수
- **명칭 기준:** 최신 브리핑의 ‘SGIS 오픈플랫폼’을 사용한다. 이전 대화에서는 ‘SGIS 공유플랫폼’으로 기록했다.
- **기록 기준:** 2026-09-30까지 사용자가 전달한 현황과 대화 중 수행한 공개 자료 검토를 구분해 요약했다. 향후 진행사항을 이 문서에 업데이트한다.

## 현재 진행 상황

### 운영 현황

| 구분 | 업무망 | 인터넷망 | 합계 |
|---|---|---|---|
| VMware 운용 서버 | 3식 | 2식 | **5식** |
| 운영 VM | 26식 | 13식 | **39식** |

운영 현황의 ‘업무망·인터넷망’과 아래 구성표의 ‘내부망·외부망’은 전달받은 표기를 그대로 기록했다. 최종 장비 구성은 아래 사용자 지정 TO-BE 표를 기준으로 관리한다.

### 전환 계획

1. **기존 VM 집약:** 기존 VMware 하이퍼바이저를 **망별 1대씩, 총 2대** 유지하고 업무망 VM 26식·인터넷망 VM 13식을 각각 해당 망의 유지 호스트로 집약한다. 나머지 기존 서버는 재구성용으로 확보하고, 집약 호스트는 MTV 이관 원본으로 유지한다.
2. **재활용 장비 재배치:** 2021년 도입 S존 VMware 장비 **TNS-2100 총 5대 확정**. 이 중 **3대는 구성 투입 예정, 2대는 여유분**으로 관리한다.
3. **인프라 재구성:** VMware → Red Hat OpenShift(OVE) 전환
4. **VM 마이그레이션:** MTV를 활용한 VM 이관. 브리핑상 **예상 소요기간은 2개월**이며, 전체 사업 기간에 해당하는지는 별도 확인한다.

### 예상 일정 — 2026-09-30 업데이트

| 시기 | 예정 작업 | 상태 |
|---|---|---|
| 2026년 10월 | 사전 준비: 행정작업 및 장비 재배치 후 전기 포설 관련 작업 진행 | 예정 |
| 2026년 11월부터 | OpenShift 전환 및 MTV 관련 본 작업 시작 | 착수 예정 |

기존에 전달받은 MTV 예상 소요기간 **2개월**은 유지한다. 본 작업 내 인프라 재구성·MTV의 상세 일정과 실제 완료 예정일은 미확정이며, 11월 착수만으로 종료 월을 확정하지 않는다. 망별 VM 집약 태스크의 구체적인 수행일도 별도 협의한다.

### 최종 장비 구성 기준 — AS-IS / TO-BE

2026-09-30 사용자가 최종 장비 구성 기준으로 지정한 표이다. 아래 TO-BE 역할과 비고를 기준으로 관리하며, 구축 완료를 뜻하지 않는다.

| 망 구분 | 구성 현황(AS-IS) | 전환 구성(TO-BE) | 비고 |
|---|---|---|---|
| 외부망 | - | Master Node | 재활용 장비(정보 1과) |
| 외부망 | 외부 HV#01 | Bastion | 기존장비 재구성 |
| 외부망 | 외부 HV#02 | Worker Node#01 | 기존장비 재구성 |
| 외부망 | 외부 HV#03 | Worker Node#02 | 기존장비 재구성 |
| 내부망 | - | Master Node | 재활용 장비(정보 1과) |
| 내부망 | 내부 HV#01 | Bastion | 재활용 장비(정보 1과) |
| 내부망 | 내부 HV#02 | Worker Node#01 | 기존장비 재구성 |
| 내부망 | 내부 HV#03 | Worker Node#02 | 기존장비 재구성 |

**구성표 기록 기준**

- 외부망·내부망 모두 TO-BE는 Master Node, Bastion, Worker Node#01, Worker Node#02로 기록한다.
- 비고는 **기존장비 재구성 5개 행 + 재활용 장비 3개 행**이며, 내부망 Bastion은 사용자 표에 따라 재활용 장비로 기록한다.
- 기존 운영 현황 5식과 AS-IS의 HV 표기 6개는 서로 다른 원문 기록으로 보존한다. 이 차이를 근거로 사용자가 지정한 TO-BE를 수정하지 않는다.
- Master의 상세 물리·가상 구성 및 HA 구성은 표에 명시되지 않았으므로 임의로 추가하지 않는다.

### 작업 태스크 02 — MTV 스토리지 용량 및 증설량 개략 산정

**상태:** 입력 자료 확보 대기. 현재는 용량 수치가 없어 필요 TB 및 증설량을 확정하지 않았다.

| 필요한 자료 | 확인 내용 |
|---|---|
| 이관 대상 VM 디스크 | 업무망·인터넷망별 가상 디스크 설정 용량 합계 및 실제 사용량 |
| EMC 풀 현황 | 풀별 전체·사용·실제 잔여 용량, 이 사업에 할당 가능한 잔여분 |
| 할당 정책 | 원본·대상 Thin/Thick, 데이터 절감 기능 및 예약·할당 제한 |
| 이관·원본 보관 계획 | 일괄/단계별 이관, 원본 삭제 가능 시점, 스냅샷 및 변경 데이터 보관량 |
| 대상 구성 | CSI 지원 여부, 볼륨 모드, 필요한 임시 공간 및 운영 여유 공간 |

**초기 산정 가정:** 같은 EMC에 원본을 유지하면서 일반적인 복사 방식으로 이관하고, Thin·압축·중복제거 절감 효과 및 원본 삭제로 회수할 공간은 우선 제외한다. 아래는 공식 제품 최소 요구량이 아닌 협의용 보수적 산정 방식이다.

```text
D = 이관 대상 VM의 가상 디스크 설정 용량 합계
O = 대상 볼륨 오버헤드 및 별도 플랫폼 볼륨 등 추가 공간
S = 이관 중 추가로 발생하는 스냅샷·임시 공간
G = 이관 기간 증가분 및 운영 여유 공간
F = 원본을 유지한 현재 상태에서 이 사업에 사용 가능한 EMC 풀의 실제 잔여 용량

추가 필요 공간 추정 = D + O + S + G
증설 필요 유효 용량 추정 = max(0, D + O + S + G - F)
```

업무망·인터넷망이 서로 다른 풀을 사용하면 풀별로 계산한다. 같은 풀을 공유하면 잔여 용량 F를 중복 계산하지 않는다. F는 기존 원본이 차지한 공간을 이미 제외한 값이므로 원본 용량을 다시 더하지 않는다. 실제 신규 디스크 구매 용량은 RAID·예비 디스크 등 구성 확인 후 환산한다.

대상 볼륨의 파일시스템 오버헤드 등은 구성에 따라 달라지므로 고정 비율을 확정하지 않았다. [MTV 스토리지 요구사항 참고](https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.9/html-single/installing_and_using_the_migration_toolkit_for_virtualization/index). 이 참고 버전은 본 사업의 MTV 버전 확정을 뜻하지 않는다.

## 현재 이슈 및 확인 요청사항

### 재활용 TNS-2100의 드라이버·펌웨어 호환성 확인

- 대상: **2021년 도입 S존 VMware 장비 TNS-2100**, 총 5대 확정
- 구성 방향: **3대 투입 예정 + 2대 여유분**
- 확인 사항: Bastion **RHEL 9.8**, OCP 4.22의 **RHEL 9.8 기반 RHCOS**와 실제 NIC·RAID/HBA 드라이버 및 BIOS·BMC 등 펌웨어의 지원 범위
- 상태: 실제 장비 기준 제조사 확인·검증 대기. 호환 장애가 확인된 상태는 아님
- 기존 eSlim SU7-2212P는 최신 사용자 정정에 따라 **대상에서 제외**하며, 2019년 도입 eSlim 노후화 이슈는 과거 검토 이력으로만 보존한다.

## 호환성 검토 현황

아래는 대화 중 공개 자료로 확인한 범위이며, 실장비 검증이나 제조사 지원 확약을 받은 결과는 아니다.

| 대상 | 현재 검토 상태 |
|---|---|
| TNS-2100 | Red Hat 제품 카탈로그 등록 확인. 실제 인수 장비 구성과 대상 버전의 인증 범위는 미확인 |
| NIC·RAID·펌웨어 | 실제 장착 부품 및 버전 기준의 지원 여부 확인 필요 |
| EMC / OCP CSI | 스토리지 모델과 연결 방식 확인 후 지원 드라이버 및 대상 OCP 버전 대조 필요 |

**OCP 4.22의 Master·Worker OS는 RHEL 9.8 기반 RHCOS로 검토한다.** Bastion의 RHEL 9.8 설치·지원 확인만으로 OCP 노드 호환성 확인을 완료 처리하지 않는다. 제조사 확인에는 RHEL 9.8 기반 RHCOS, 장착 NIC·RAID 및 펌웨어 지원 범위를 명시한다.

### 버전 및 릴리스 확인 — 2026-09-30

- [Red Hat 버전 대응표](https://access.redhat.com/articles/6907891): **OCP 4.22 ↔ RHEL 9.8 기반 RHCOS** 확인.
- [RHEL 공식 다운로드 안내](https://developers.redhat.com/products/rhel/download): 조회 결과 RHEL 9.8의 릴리스 날짜는 **2026-05-19**로 안내되어 있다.
- [OCP 4.22 공식 릴리스 노트](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html/release_notes/ocp-4-22-release-notes): 4.22 제공 및 패치 릴리스 확인.
- 따라서 현재 확인한 공식 자료 기준으로는 릴리스 대기 상태로 기록하지 않는다. 11월 구축에 사용할 정확한 4.22.z·RHCOS 이미지, MTV·CSI 지원 조합 및 실제 장비 호환성은 아직 확정하지 않았다.
