01. 작업 개요

본 작업은 국가데이터처 SGIS 오픈플랫폼의 VMware 가상머신을 OpenShift Virtualization으로 이관하는 실제 작업의 순서와 명령, 완료 기준을 정리한 계획입니다. 망별로 Bastion과 Master KVM 서버를 구축하여 폐쇄망 UPI 방식으로 OpenShift 클러스터를 설치하고, 비어 있는 하이퍼바이저를 Worker1로 전환한 뒤 MTV로 VM을 이관합니다. 이관과 확인이 끝나면 원본 하이퍼바이저를 Worker2로 전환합니다.

외부망을 먼저 수행하고 내부망을 나중에 수행합니다. 외부망에서 검증한 절차와 소요 시간을 내부망에 적용하며, 내부망은 외부망과 다른 부분만 08장에 정리합니다.

노드 네트워크bond0(관리망, mode 1, 노드 IP·기본 게이트웨이), bond1(nas, LACP, VLAN 없음), bond2(svc, LACP, VLAN 130 trunk)를 RHCOS 설치 전에 live ISO에서 만들고, 설치 후 NNCP로 br-nas(bond1)·br-svc(bond2) 브리지를 만듭니다. VM은 NAD svc-130, nas로 연결합니다.
이관 방식Cold 이관이며 VDDK 네트워크 복사(vCenter 443, ESXi 443·902)를 사용합니다. VM은 1대씩 이관합니다. VMware Tools는 설치하지 않으므로 원본 VM은 게스트 안에서 직접 종료하고, 이관 후 IP는 사전 기록과 대조하여 필요 시 게스트 안에서 직접 설정합니다.
스토리지VM 디스크는 Worker의 FC HBA로 연결한 스토리지에 둡니다. StorageClass와 CSI 드라이버 구성은 스토리지 엔지니어가 수행하며, RWX 지원 여부를 확인한 뒤 이관을 시작합니다.
업데이트·백업OSUS(업데이트 서비스)를 기본 구성으로 포함하고 CVO를 내부 OSUS에 연결합니다. etcd 백업은 매일 Bastion이 nas 망의 NFS에 보관합니다.
표기명령의 <…>는 현장 값으로 바꾸어 입력합니다. ${MIRROR_HOST} 같은 변수는 02-1의 환경변수 파일 값입니다. IP·호스트명 실제 값은 구축설계서 IP 기입표를 따릅니다.
주의할 점
  • Worker 전환은 원복이 불가합니다. 하이퍼바이저에 RHCOS를 설치하면 ESXi와 기존 설정이 삭제됩니다. Worker1 전환(04-4)과 Worker2 전환(07-2)은 바로 앞의 확인 목록(04-2, 07-1)을 모두 충족한 경우에만 진행합니다.
  • Worker2 전환 이후에는 원본 VM으로 복귀할 수 없습니다. 원본 HV#01을 전환하면 VMware 환경과 vCenter가 함께 사라집니다. 모든 VM의 이관 후 확인과 업무 담당의 원본 불필요 확인이 끝난 뒤에 진행합니다.
  • 원본 VM은 끈 상태로 보존합니다. 이관이 끝난 원본 VM은 Worker2 전환 전까지 삭제하지 않으며, 문제가 생기면 원본 VM을 다시 기동하여 서비스를 복구합니다.
  • DNS VM은 모든 VM 이관이 끝날 때까지 유지합니다. MTV는 vCenter·ESXi에 이름으로 접속하므로, DNS VM을 먼저 끄면 이관이 중단될 수 있습니다.

02. Bastion 구축 (외부망)

재활용 장비(TNS-2100)에 RHEL 9.8로 Bastion을 구축합니다. 관리망 2포트는 bond0, 신규 포설한 nas 2포트는 bond1(LACP, 802.3ad)로 구성합니다. nas 포트는 etcd 백업을 NFS에 보관하는 데 사용합니다. Bastion은 DNS, 로드밸런서, NTP, Ignition 배포용 HTTP 서버, 미러 레지스트리를 제공하며, OpenShift 노드와 이관 Pod가 vCenter·ESXi 이름을 해석할 수 있도록 vCenter와 원본 ESXi의 A 레코드도 Bastion DNS에 등록합니다.

02-1. 환경변수 파일

Bastion에서 실행하는 명령에는 ${MIRROR_HOST}, ${INSTALL_DIR} 같은 변수가 반복되므로 한 파일에 모아 둡니다. 암호와 토큰은 넣지 않고 인증 파일은 경로만 적습니다. D2M_DIR은 02-7에서 추가합니다.

Bastion (root)
cat > ~/ocp.env <<'EOF'
MIRROR_HOST=<미러 레지스트리 호스트 이름(포트 제외)>
MIRROR_ORG=<Quay 조직 이름>
DOMAIN=<클러스터 이름.base domain>
BASTION_IP=<Bastion 관리망 IP>
HTTP_PORT=<Ignition HTTP 서버 포트>
YAML_DIR=<install-config.yaml을 둘 디렉터리>
INSTALL_DIR=<설치 디렉터리>
AUTH_FILE=<미러 레지스트리 인증 파일 경로>
ROOT_CA=<미러 레지스트리 root CA 파일 경로>
EOF
chmod 0600 ~/ocp.env
vi ~/ocp.env

값을 채울 때 <…>는 꺾쇠까지 지우고 값만 남깁니다. 아래 첫 줄은 꺾쇠가 남은 줄을 찾으므로 출력이 없어야 합니다. 둘째 줄은 아직 정하지 않은 변수를 「비어 있음」으로 알려 줍니다.

Bastion (root, bash)
grep -nE '^[A-Z0-9_]+=.*[<>]' ~/ocp.env
source ~/ocp.env && for v in MIRROR_HOST MIRROR_ORG DOMAIN BASTION_IP HTTP_PORT YAML_DIR INSTALL_DIR AUTH_FILE ROOT_CA D2M_DIR; do [ -n "${!v}" ] || echo "비어 있음: $v"; done
변수는 해당 셸에서만 유지됩니다. 새로 접속하면 명령 전에 source ~/ocp.env를 먼저 실행합니다. DNS zone 파일, install-config.yaml처럼 vi로 작성하는 파일 안의 <도메인> 자리는 직접 값을 입력합니다.

02-2. CLI 설치와 방화벽

반입한 압축 파일에서 oc, oc-mirror, openshift-install, butane을 /usr/local/bin에 설치합니다.

Bastion (root)
cd <반입 경로>
tar -xzf openshift-client-linux-amd64-rhel9-4.22.22.tar.gz -C /usr/local/bin oc kubectl
tar -xzf openshift-install-linux-4.22.22.tar.gz -C /usr/local/bin openshift-install
tar -xzf oc-mirror.rhel9.tar.gz -C /usr/local/bin oc-mirror
chmod 0755 /usr/local/bin/oc-mirror
install -m 0755 butane-amd64 /usr/local/bin/butane
oc version --client
oc-mirror version
openshift-install version
butane --version

네 명령이 모두 버전을 출력하면 완료입니다. 방화벽은 끄지 않고 필요한 포트를 허용합니다. 80·443·6443·22623은 02-9에서 같은 방식으로 허용합니다.

Bastion (root)
firewall-cmd --permanent --add-service=dns
firewall-cmd --permanent --add-port=8443/tcp --add-port=${HTTP_PORT}/tcp
firewall-cmd --reload
firewall-cmd --list-all

원복은 --add-port 대신 --remove-port를 사용합니다. HTTP 포트가 SELinux에서 httpd에 허용되지 않은 경우 semanage port -a -t http_port_t -p tcp <HTTP 포트>로 추가합니다.

02-4. 도구와 HTTP 서버

podman·jq는 미러 레지스트리와 인증 작업에, httpd는 노드가 Ignition 파일과 설치 스크립트를 받는 HTTP 서버로 사용합니다. 로드밸런서가 같은 Bastion에서 80을 사용하므로 HTTP 서버는 별도 포트로 변경합니다.

Bastion (root)
dnf install -y podman jq httpd
test -e /etc/httpd/conf/httpd.conf.pre-ocp \
  || cp -a /etc/httpd/conf/httpd.conf /etc/httpd/conf/httpd.conf.pre-ocp
sed -i "s/^Listen 80\$/Listen ${HTTP_PORT}/" /etc/httpd/conf/httpd.conf
systemctl enable httpd --now
ss -tlnp | grep ":${HTTP_PORT}"

ss에 HTTP 포트가 LISTEN으로 보이면 완료입니다. 보이지 않으면 systemctl status httpd로 오류를 확인하고 SELinux 포트 허용을 먼저 확인합니다.

02-5. DNS 구성

api, api-int, *.apps와 모든 노드의 이름 및 역방향(PTR) 레코드는 설치 전에 등록되어 있어야 합니다. RHCOS는 역방향 레코드로 호스트 이름을 정하고 CSR 생성에도 사용합니다.

options { … }; 안에서 listen-on, allow-query, recursion, dnssec-validation만 확인·수정하고 파일 전체는 바꾸지 않습니다. 기본안은 listen-on port 53 { 127.0.0.1; <Bastion 관리망 IP>; };, allow-query { localhost; <관리망 대역>; };, 외부 이름 해석이 필요 없으면 recursion no;, 폐쇄망이므로 dnssec-validation no;입니다. 질의 허용 대역과 재귀 질의는 고객사 정책에 맞춥니다.

};

    type master;

<끝 숫자> IN PTR bastion.<도메인>.
<끝 숫자> IN PTR api.<도메인>.
<끝 숫자> IN PTR api-int.<도메인>.
; 노드마다 PTR 한 줄. 위 세 줄처럼 같은 IP에 이름이 여럿이면 줄을 여러 개 둔다. `<역방향 zone 이름>`은 노드 대역의 앞 세 숫자를 거꾸로 쓴 것이다. 예: 대역이 `10.20.30.0/24`이면 `30.20.10`이고 `<끝 숫자>`는 주소의 마지막 숫자다

역방향 zone 이름은 노드 대역의 앞 세 자리를 거꾸로 쓴 값입니다(예: 10.20.30.0/24 → 30.20.10). 노드 IP가 한 /24에 모두 들어가지 않으면 대역마다 역방향 zone을 만듭니다.

02-6. 미러 레지스트리(Quay) 설치

mirror registry for Red Hat OpenShift를 Bastion에 설치합니다. 2.0부터 SQLite를 사용하므로 --sqliteStorage를 지정합니다. 레지스트리 이름은 DNS에 등록되어 있어야 하며 서버 인증서의 subjectAltName에 같은 이름이 들어가야 합니다. 고객사가 인증서를 제공하거나 PKI 정책이 있으면 아래 openssl 구간 대신 제공받은 키와 인증서를 사용합니다.

관리자 암호는 8자 이상이며 공백이 없어야 합니다. 조건에 맞지 않으면 설치 메시지는 성공으로 나오지만 계정이 만들어지지 않아 로그인이 실패합니다. 아래 블록은 파일(예: install_quay.sh)로 저장하여 sh로 실행합니다(셸에 붙여 넣으면 exit가 접속을 종료합니다).

Bastion (root) · install_quay.sh
REG_HOME=<설치 루트>        # mirror-registry 압축을 푼 디렉터리
REG_URL=${MIRROR_HOST}   # ocp.env의 값(DNS에 등록된 이름)

mkdir -p "${REG_HOME}"
tar -xvf <반입 경로>/mirror-registry-amd64.tar.gz -C "${REG_HOME}"

# 이미 설치한 흔적이 있으면 멈춘다(되돌릴 수 없는 재설치를 막는다)
if test -e "${REG_HOME}/quay"; then
  printf 'Existing Quay directory, aborting: %s\n' "${REG_HOME}/quay" >&2
  exit 1   # 이 블록은 파일(예: install_quay.sh)로 저장해 sh로 실행한다. 셸에 그대로 붙여 넣으면 exit가 SSH 세션을 끝낸다
fi

mkdir -p "${REG_HOME}/quay/data" "${REG_HOME}/quay/cert.d"
cd "${REG_HOME}/quay/cert.d" || exit 1

# 사설 root CA와 서버 인증서(고객사 PKI가 있으면 이 구간을 건너뛴다)
openssl genrsa -out rootCA.key 4096
openssl req -x509 -new -nodes -key rootCA.key -sha256 -days <root CA 유효일수> \
  -out rootCA.crt -subj "/O=<조직>/CN=<root CA 이름>"
openssl genrsa -out "${REG_URL}.key" 4096
openssl req -new -key "${REG_URL}.key" -out "${REG_URL}.csr" -subj "/CN=${REG_URL}"
cat > "${REG_URL}.cnf" <<EOF
[ v3_ca ]
basicConstraints = CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = DNS:${REG_URL}
EOF
openssl x509 -req -in "${REG_URL}.csr" -CA rootCA.crt -CAkey rootCA.key -CAcreateserial \
  -out "${REG_URL}.crt" -days <서버 인증서 유효일수> -sha256 \
  -extfile "${REG_URL}.cnf" -extensions v3_ca
cp rootCA.crt /etc/pki/ca-trust/source/anchors/
update-ca-trust extract

# 관리자 계정과 암호는 문서와 shell history에 남기지 않고 설치할 때 직접 입력한다
read -r -p 'Quay admin user: ' INIT_USER
read -r -s -p 'Quay admin password: ' INIT_PASSWORD
printf '\n'

"${REG_HOME}/mirror-registry" install -v \
  --initUser "${INIT_USER}" \
  --initPassword "${INIT_PASSWORD}" \
  --quayHostname "${REG_URL}:8443" \
  --quayRoot "${REG_HOME}/quay" \
  --sqliteStorage "${REG_HOME}/quay/sqlitestorage" \
  --quayStorage "${REG_HOME}/quay/quaystorage" \
  --sslKey "${REG_HOME}/quay/cert.d/${REG_URL}.key" \
  --sslCert "${REG_HOME}/quay/cert.d/${REG_URL}.crt"
Bastion (root)
podman ps
podman login ${MIRROR_HOST}:8443
curl --cacert ${ROOT_CA} https://${MIRROR_HOST}:8443/health/instance
완료 기준 — Quay 컨테이너가 Up이고 podman login이 Login Succeeded!를 출력하며, --cacert 조회가 TLS 오류 없이 응답합니다. 레지스트리 주소는 이후 모든 명령에서 ${MIRROR_HOST}:8443처럼 포트까지 같게 씁니다.

원복: "${REG_HOME}/mirror-registry" uninstall -v --quayRoot "${REG_HOME}/quay" 후 rm -rf "${REG_HOME}/quay". uninstall에도 설치 때와 같은 --quayRoot를 지정해야 실제로 삭제됩니다.

02-9. 로드밸런서(HAProxy)

로드밸런서는 Layer 4(TCP)로 구성합니다. API(6443)와 Machine Config Server(22623) 풀에는 bootstrap과 master 3대를 넣고, 6443은 /readyz로 상태를 확인합니다. bootstrap은 backup으로 두어 master가 올라온 뒤에는 트래픽이 가지 않게 합니다. 앱 인그레스(443·80) 풀은 master가 스케줄 불가이므로 Worker만으로 구성하며, Worker1이 Ready가 되어 router Pod가 뜬 뒤(04-5) 추가합니다.

Bastion (root)
dnf install -y haproxy
test -e /etc/haproxy/haproxy.cfg_default \
  || cp -a /etc/haproxy/haproxy.cfg /etc/haproxy/haproxy.cfg_default
vi /etc/haproxy/haproxy.cfg

haproxy.cfg_default는 원복용 원본입니다. 기존 내용을 모두 지우고 아래로 교체합니다(기본 frontend 블록이 남으면 80·443이 겹칩니다).

  daemon

  option redispatch
  retries 3
  timeout http-request 10s
  timeout queue 1m

  timeout client 1m

  server master3 <master3 IP>:6443 verify none check check-ssl inter 10s fall 2 rise 3

03. Master KVM 서버 구성 및 클러스터 설치 (외부망)

Master KVM 서버에 master VM 3대와 bootstrap VM을 만들고 OpenShift를 설치합니다. 설치 순서는 bootstrap 설치 → bootstrap API 확인 → master 3대 설치 → CSR 승인 → bootstrap 완료 확인 → 미러 리소스 적용입니다. 설치 완료(install-complete)는 master가 스케줄 불가이므로 Worker1이 Ready가 된 뒤(04-5)에 확인합니다.

03-1. Master KVM 서버 구성

03-2. install-config 작성

${YAML_DIR}/install-config.yaml을 아래 기본 구조로 작성한 뒤 pullSecret, sshKey, additionalTrustBundle, imageDigestSources를 순서대로 파일 끝에 이어 붙입니다. 같은 항목을 두 번 붙이면 키가 중복되어 manifest 생성이 실패하므로, 틀린 경우 파일을 지우고 처음부터 다시 작성합니다.

${YAML_DIR}/install-config.yaml (기본 구조)
apiVersion: v1
baseDomain: <base domain>
compute:
- hyperthreading: Enabled
  name: worker
  replicas: 0
controlPlane:
  hyperthreading: Enabled
  name: master
  replicas: 3
metadata:
  name: <클러스터 이름>
networking:
  clusterNetwork:
  - cidr: 10.128.0.0/14
    hostPrefix: 23
  machineNetwork:
  - cidr: <노드 IP가 속한 관리망 대역>
  networkType: OVNKubernetes
  serviceNetwork:
  - 172.30.0.0/16
platform:
  none: {}
fips: false
항목기준
baseDomain · metadata.name합쳐서 클러스터 도메인이 되며 DNS 레코드(02-5)와 같아야 합니다.
machineNetwork노드 IP(bond0)가 속한 관리망 대역이며 DNS·로드밸런서 주소와 같은 대역입니다.

compute replicas 0Worker는 설치 후 CSR 승인으로 편입합니다.

pullSecret에는 미러 레지스트리 인증만 넣습니다. 클러스터는 이미지를 미러 레지스트리에서만 받습니다. 인증 파일 내용은 화면에 출력하지 않습니다.

Bastion (root)
podman login --authfile ${AUTH_FILE} ${MIRROR_HOST}:8443
test -s ${AUTH_FILE}
printf "pullSecret: '" >> ${YAML_DIR}/install-config.yaml
jq -c . ${AUTH_FILE} | tr -d '\n' >> ${YAML_DIR}/install-config.yaml
printf "'\n" >> ${YAML_DIR}/install-config.yaml
chmod 0600 ${YAML_DIR}/install-config.yaml

sshKey에는 Bastion root의 공개키를 넣습니다(없으면 ssh-keygen -t ed25519로 생성). 이 키는 노드 진단과 etcd 백업(07-4)에 사용합니다. additionalTrustBundle은 미러 레지스트리의 root CA이며, imageDigestSources는 oc-mirror가 만든 IDMS의 매핑을 그대로 옮깁니다.

Bastion (root)
printf "sshKey: '" >> ${YAML_DIR}/install-config.yaml
tr -d '\n' < /root/.ssh/id_ed25519.pub >> ${YAML_DIR}/install-config.yaml
printf "'\n" >> ${YAML_DIR}/install-config.yaml

printf "additionalTrustBundle: |\n" >> ${YAML_DIR}/install-config.yaml
sed 's/^/  /' ${ROOT_CA} >> ${YAML_DIR}/install-config.yaml

printf 'imageDigestSources:\n' >> ${YAML_DIR}/install-config.yaml
awk '/- mirrors:/ {p=1; print "  - mirrors:"}
     p && /^[[:space:]]*- / && !/- mirrors:/ {
       sub(/^[[:space:]]*-[[:space:]]*/, ""); print "    - " $0
     }
     p && /source:/ {
       sub(/^[[:space:]]*/, ""); print "    " $0; p=0
     }' \
  ${D2M_DIR}/working-dir/cluster-resources/idms-*.yaml \
  >> ${YAML_DIR}/install-config.yaml
grep -nE '^(apiVersion|baseDomain|pullSecret|sshKey|additionalTrustBundle|imageDigestSources):' ${YAML_DIR}/install-config.yaml | cut -c1-40

03-3. manifest 생성, master 스케줄 불가, 시간 동기화

03-4. Ignition 생성과 설치 스크립트

Ignition 파일은 생성 후 12시간 안에 사용합니다(내부 인증서가 24시간 후 만료되며 16~22시간 사이에 갱신이 일어납니다). 설치 후 Worker를 추가하므로 설치 디렉터리 원본을 보관합니다(인증 정보가 있으므로 비공개).

Bastion (root)
openshift-install create ignition-configs --dir ${INSTALL_DIR}
cp -a ${INSTALL_DIR} ${INSTALL_DIR}.orig

role별 Ignition 3개만 HTTP 폴더에 복사하고, 노드 콘솔에서 SHA-512를 직접 입력하지 않도록 role별 설치 스크립트에 파일 이름과 SHA-512를 미리 채워 둡니다.

Bastion (root)
install -d -m 0750 -o root -g apache <HTTP 문서 루트>/<디렉터리>
install -m 0640 -o root -g apache \
  ${INSTALL_DIR}/bootstrap.ign \
  ${INSTALL_DIR}/master.ign \
  ${INSTALL_DIR}/worker.ign \
  <HTTP 문서 루트>/<디렉터리>/
cd <HTTP 문서 루트>/<디렉터리>
sha512sum bootstrap.ign master.ign worker.ign | tee ignition-sha512.txt

cat > install.sh <<'EOF'
#!/bin/sh
WebServerAddress=<Bastion 관리망 IP>:<HTTP 포트>/<디렉터리>
IGNITIONFILE=bootstrap.ign
IGNITION_SHA512=REPLACE_WITH_ROLE_SHA512
DstHDD=<설치 디스크>

test "${IGNITION_SHA512}" != 'REPLACE_WITH_ROLE_SHA512' || {
  echo 'set the Ignition SHA-512 first' >&2
  exit 1
}

sudo coreos-installer install \
  --ignition-url="http://${WebServerAddress}/${IGNITIONFILE}" \
  --ignition-hash="sha512-${IGNITION_SHA512}" \
  --copy-network \
  "${DstHDD}"
EOF

for ROLE in bootstrap master worker; do
  SHA=$(awk -v f="${ROLE}.ign" '$2==f {print $1}' ignition-sha512.txt)
  sed -e "s/^IGNITIONFILE=.*/IGNITIONFILE=${ROLE}.ign/" \
      -e "s/^IGNITION_SHA512=.*/IGNITION_SHA512=${SHA}/" \
      install.sh > ${ROLE}.sh
  chown root:apache ${ROLE}.sh
  chmod 0640 ${ROLE}.sh
done
grep -H -E '^(IGNITIONFILE|IGNITION_SHA512)=' bootstrap.sh master.sh worker.sh
rm install.sh

<설치 디스크>는 서버마다 다르므로(VM은 /dev/vda, 물리 서버는 /dev/sd*·/dev/nvme*) 노드 콘솔에서 lsblk로 확인한 뒤 스크립트에서 수정합니다. Ignition 파일을 다시 만들거나 바꾸면 SHA-512도 다시 채웁니다(04-3).

03-5. bootstrap과 master 설치

각 VM을 RHCOS live ISO로 부팅하고 부팅 메뉴에서 커널 인자로 정적 IP를 지정합니다. 메뉴는 5초 후 넘어가므로 바로 Tab을 눌러 커널 줄 끝에 한 칸을 띄우고 아래를 입력합니다. 형식은 주소::gateway:넷마스크:호스트명:NIC:none이며 호스트명은 비워 둡니다(DNS 역방향 조회로 자동 지정). UEFI 부팅이면 GRUB 항목 편집(e)에서 linux 줄 끝에 추가합니다.

부팅 메뉴 커널 인자
ip=<노드 IP>::<gateway>:<넷마스크>::<NIC 이름>:none nameserver=<DNS IP> rd.neednet=1

live 프롬프트가 [core@<노드 이름> ~]$로 나오면 주소와 DNS가 맞습니다. [core@localhost ~]$이면 값 또는 DNS가 틀린 것이므로 설치하지 않고 인자를 다시 확인합니다. 이어서 role별 스크립트를 받아 확인 후 실행합니다.

노드 콘솔 (core)
curl -O http://<Bastion 관리망 IP>:<HTTP 포트>/<디렉터리>/<role>.sh
lsblk
cat <role>.sh
sh <role>.sh
설치 전 확인 — cat 출력에서 WebServerAddress, IGNITIONFILE(해당 role), IGNITION_SHA512(128자리), DstHDD(lsblk의 설치 디스크)를 확인합니다. 디스크 앞부분을 덮어쓰는 작업이므로 값이 틀리면 되돌릴 수 없습니다.

Install complete.가 나오면 sudo poweroff로 끄고, 켜기 전에 VM 설정의 부팅 순서를 디스크 우선으로 바꿉니다(Boot Options에서 VirtIO Disk만 체크). 이어서 순서대로 진행합니다.

  1. bootstrap VM을 설치·기동하고 6443·22623이 열린 것을 확인합니다.
  2. wait-for bootstrap-complete 로그에 API가 올라온 것이 보이면 master 3대를 같은 방법으로 설치합니다.
  3. master가 올라오면 다른 셸에서 CSR을 승인합니다(03-6).
  4. master 3대가 Ready이고 It is now safe to remove the bootstrap resources가 나오면 bootstrap VM을 끄고 삭제합니다.

03-6. 로그인과 CSR 승인

CSR은 추가한 머신마다 1시간 안에 승인합니다. 노드마다 client 요청을 승인하면 server(kubelet serving) 요청이 이어서 올라오므로 두 번 승인합니다. platform none이므로 server 요청도 직접 승인해야 하며, 승인하지 않으면 oc exec·oc logs가 실패합니다.

04-3. Worker 전환용 worker.ign 준비

설치 후 24시간이 지난 UPI 클러스터에 설치 때 만든 worker.ign을 그대로 쓰면 인증서 오류(certificate signed by unknown authority)로 편입이 실패할 수 있습니다(KCS 4799921). HV#02를 vCenter에서 제거한 뒤에는 되돌리기 어려우므로, 전환 직전에 worker.ign 안의 인증서 값을 api-int:22623이 현재 제공하는 인증서로 미리 교체합니다. 원본은 worker.ign.backup으로 남습니다.

Bastion (worker.ign이 있는 HTTP 폴더)

sed --regexp-extended --in-place=.backup "s%base64,[a-zA-Z0-9+\/=]+%base64,$(cat ./api-int.base64)%" ./worker.ign

base64 -d ./api-int.base64 | grep -c 'BEGIN CERTIFICATE'가 1이어야 합니다. 여러 개이면 첫 인증서만 사용합니다. diff로 원본과 달라진 것을 확인하고, 소유·권한을 다른 Ignition 파일과 같게(root:apache 0640) 맞춘 뒤 worker 스크립트의 SHA-512를 갱신합니다.

Bastion (HTTP 폴더)

grep -H '^IGNITION_SHA512=' <worker용 설치 script>

원복: mv ./worker.ign.backup ./worker.ign 후 SHA-512를 다시 갱신합니다. 교체한 파일로 편입되지 않으면 클러스터에서 새로 꺼낸 파일(oc extract -n openshift-machine-api secret/worker-user-data-managed --keys=userData --to=- > worker.ign)을 사용합니다.

04-4. HV#02 제거, bond 구성, RHCOS 설치

  1. VMware 엔지니어가 HV#02를 vCenter에서 제거합니다.
  2. 스토리지 엔지니어가 HV#02의 VMFS LUN 매핑을 해제합니다. HV#02의 FC HBA와 연결은 그대로 사용하며, VM 디스크용 LUN의 multipath 설정이 MachineConfig로 필요하면 Worker1 편입 전에 worker 풀에 미리 만들어 둡니다(편입 후 적용하면 재부팅됩니다).

  4. live ISO 콘솔에서 bond 스크립트로 bond0·bond1·bond2를 만들고 확인합니다. 프로필을 지우는 순간 SSH 세션이 끊기므로 반드시 콘솔에서 실행합니다.
  5. 네트워크 담당과 bond 이중화 시험을 마친 뒤 worker.sh(03-4)로 설치합니다. --copy-network가 bond 설정을 설치된 노드로 복사합니다.
Bastion (root)

#!/bin/sh
# usage: sh worker-net.sh <노드 주소/prefix>
NODE_ADDR=${1:?usage: sh worker-net.sh <노드 주소/prefix>}
NODE_GW=<gateway>
NODE_DNS=<DNS IP>
BOND0_PORTS="<NIC 이름 1> <NIC 이름 2>"
BOND1_PORTS="<NIC 이름 3> <NIC 이름 4>"   # nas
BOND2_PORTS="<NIC 이름 5> <NIC 이름 6>"   # svc

# loopback을 뺀 모든 프로필을 지운다(DHCP·부팅 인자 프로필이 설치된 노드로 복사되지 않게)
nmcli -g UUID,TYPE c show | awk -F: '$2!="loopback" {print $1}' | while read -r u; do
  nmcli c delete uuid "$u"
done

mkbond() {
  name=$1; opts=$2; shift 2
  nmcli c add type bond con-name "$name" ifname "$name" bond.options "$opts"
  n=1
  for port in "$@"; do
    nmcli c add type ethernet con-name "${name}-port${n}" ifname "$port" master "$name" slave-type bond
    n=$((n + 1))
  done
}

mkbond bond0 "mode=active-backup,miimon=100" $BOND0_PORTS
nmcli c modify bond0 ipv4.addresses "$NODE_ADDR" ipv4.method manual ipv4.gateway "$NODE_GW" \
  ipv4.dns "$NODE_DNS" ipv6.method disabled autoconnect yes

# bond1 = nas: VLAN 없음(스위치 access 포트), LACP
mkbond bond1 "mode=802.3ad,miimon=100,lacp_rate=fast,xmit_hash_policy=layer2+3" $BOND1_PORTS
nmcli c modify bond1 ipv4.method disabled ipv6.method disabled autoconnect yes

# bond2 = svc: VM 서비스망 VLAN 130 trunk, LACP

07-4. etcd 백업 설정

master VM과 KVM 서버는 관리망에만 있으므로 nas 망에 연결된 Bastion이 NFS를 마운트하고, Bastion의 systemd timer가 master 한 대에서 백업을 받아 매일 보관합니다. 이 자동화는 고객사 운영 자동화이며 Red Hat 지원 방법이 아닙니다(자동 백업 Backup CR은 Technology Preview).

시작 시점 — 첫 백업은 설치 24시간 후 첫 인증서 교체가 끝난 다음에 실행합니다. 설치 후 24시간 안에는 클러스터를 끄지 않습니다. 교체 여부는 oc describe secret/csr-signer-signer -n openshift-kube-controller-manager-operator의 유효 기간이 약 30일로 바뀐 것으로 확인하며, 설치 시각은 oc get clusterversion version -o jsonpath='{.metadata.creationTimestamp}'로 확인합니다.

백업은 master 한 대에서 cluster-backup.sh를 실행하며 결과는 snapshot_*.db와 static_kuberesources_*.tar.gz 두 파일입니다. 복구에는 둘 다 필요합니다. 수동 절차는 아래와 같습니다.

chroot /host
/usr/local/bin/cluster-backup.sh /home/core/assets/backup

① NFS 마운트 — fstab 줄이 이미 있는지 먼저 확인합니다(두 번 실행하면 중복됩니다). 쓰기 시험이 실패하면 NFS 담당과 export·권한을 정합니다.

mkdir -p /mnt/etcd-backup
echo '<NFS 서버>:<export 경로> /mnt/etcd-backup nfs4 defaults,_netdev 0 0' >> /etc/fstab
mount /mnt/etcd-backup
mkdir -p /mnt/etcd-backup/ocp
touch /mnt/etcd-backup/ocp/.write-test && rm /mnt/etcd-backup/ocp/.write-test

② master SSH 접속 — 03-2에서 sshKey로 넣은 공개키의 개인키를 root가 사용합니다. 서비스는 비대화형이므로 master 3대의 호스트 키를 known_hosts에 미리 등록합니다.

ssh-keyscan -H <master-0 호스트명> <master-1 호스트명> <master-2 호스트명> >> /root/.ssh/known_hosts
ssh -o BatchMode=yes core@<master-0 호스트명> true

③ 백업 스크립트 — /usr/local/sbin/etcd-backup.sh. NFS가 마운트되지 않으면 실행하지 않고, 동시 실행은 flock으로 막으며, 보관 기간이 지난 날짜 폴더만 삭제합니다. control plane operator가 Progressing이면 cluster-backup.sh가 실패하며, 자동으로 --force를 붙이지 않고 실패가 보이게 합니다.

#!/bin/bash
set -euo pipefail
umask 077
exec 9>/var/lock/etcd-backup.lock
flock -n 9 || { echo "another etcd backup is running" >&2; exit 1; }
MASTER="<master-0 호스트명>"
BASE=/mnt/etcd-backup/ocp
RETENTION_DAYS="<보관 일수>"
REMOTE_DIR=/home/core/assets/backup
[[ "${RETENTION_DAYS}" =~ ^[1-9][0-9]*$ ]] || { echo "RETENTION_DAYS must be a positive integer" >&2; exit 1; }
mountpoint -q /mnt/etcd-backup || { echo "NFS is not mounted" >&2; exit 1; }
DEST="${BASE}/$(date +%Y%m%d-%H%M%S)"
mkdir -p "${DEST}"
trap 'rc=$?; [ "${rc}" -eq 0 ] || rm -rf "${DEST}"' EXIT
ssh -o BatchMode=yes core@"${MASTER}" "sudo rm -rf ${REMOTE_DIR} && sudo /usr/local/bin/cluster-backup.sh ${REMOTE_DIR} && sudo chown -R core:core /home/core/assets"
scp -o BatchMode=yes "core@${MASTER}:${REMOTE_DIR}/*" "${DEST}/"
find "${BASE}" -mindepth 1 -maxdepth 1 -type d -name '20??????-??????' -mtime +"${RETENTION_DAYS}" -exec rm -rf {} +

④ systemd 서비스·timer — 실행 시각은 업무가 적은 시간으로 정합니다.

# /etc/systemd/system/etcd-backup.service
[Unit]
Description=etcd backup to nas NFS
RequiresMountsFor=/mnt/etcd-backup
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
TimeoutStartSec=30min
ExecStart=/usr/local/sbin/etcd-backup.sh
# /etc/systemd/system/etcd-backup.timer
[Unit]
Description=daily etcd backup

[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true

[Install]
WantedBy=timers.target
chmod 700 /usr/local/sbin/etcd-backup.sh
systemctl daemon-reload

⑤ 첫 실행과 timer 활성화 — 설치 24시간 후에 실행합니다. NFS에 두 파일이 생겼는지와 journalctl -u etcd-backup.service 출력을 확인합니다.

systemctl start etcd-backup.service
systemctl enable --now etcd-backup.timer
systemctl list-timers etcd-backup.timer

⑥ 정기 점검 — 폐쇄망이라 실패 알림이 없으므로 정해진 주기마다 확인합니다. 최근 날짜 폴더가 이틀 안이어야 하며, 지정한 master가 내려가 있으면 MASTER를 다른 master로 바꿔 수동 실행합니다.

systemctl list-timers etcd-backup.timer
ls -lt /mnt/etcd-backup/ocp | head
journalctl -u etcd-backup.service -n 30 --no-pager

⑦ SSH 키 보관 — 복원 절차는 각 control plane 노드에 SSH 접속을 전제로 하므로, 백업 스크립트가 쓰는 키 쌍을 함께 보관합니다. 개인키는 권한 600으로 접근을 제한하며 두 해시가 같아야 합니다.

KEY=<백업 스크립트가 쓰는 개인키 경로>
install -d -m 700 /mnt/etcd-backup/ocp-ssh
install -m 600 "${KEY}" /mnt/etcd-backup/ocp-ssh/
install -m 644 "${KEY}.pub" /mnt/etcd-backup/ocp-ssh/
sha256sum "${KEY}" "/mnt/etcd-backup/ocp-ssh/$(basename "${KEY}")"

클러스터 업데이트 전에도 백업을 받으며, 복구는 같은 z-stream 백업으로만 가능하므로 4.22.22 백업을 별도로 보관합니다. etcd 암호화를 사용하면 static_kuberesources 파일에 암호화 키가 들어 있으므로 스냅샷과 분리하여 보관합니다.

원복 — timer를 끄고 설정을 지웁니다. 이미 쌓인 백업 폴더는 지우지 않으며 fstab은 ①에서 추가한 줄만 삭제합니다.

rm /etc/systemd/system/etcd-backup.service /etc/systemd/system/etcd-backup.timer /usr/local/sbin/etcd-backup.sh
