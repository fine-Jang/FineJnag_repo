# 국데처 SGIS OpenShift 구축설계서 v1.0 릴리스 기록

작업계획서 v2.8과 별도로 **내부 구축팀용 구축설계서**를 새로 만든 첫 버전입니다. 반영본은 [SGIS_OCP_BuildDesign_v1.0.html](SGIS_OCP_BuildDesign_v1.0.html)입니다. 기존 작업계획서(v2.8 이하)는 수정하지 않았습니다.

## 문서 기준

- 구축설계서: 내부 구축팀용, HTML. 설계 값의 기준 문서이며 작업계획서와 값이 다르면 이 문서를 따릅니다.
- 작업계획서: 고객 제출용. 구축설계서 완성 후 이를 바탕으로 정리할 예정입니다(설계 상세 삭제는 보류).
- 미확정 값은 본문에 `TBD`로 표시하고 09장 확정 항목에 담당별로 모았습니다.

## v1.0 구성

1. **01 개요**: 설계 범위, 적용 버전(OCP 4.22 / RHCOS·RHEL 9.8 / MTV 2.12 / PowerMax CSI TBD).
2. **02 아키텍처**: 망별 장비 재구성 구성도(AS-IS → TO-BE, 신규), 장비별 역할 배정 표.
3. **03 하드웨어·용량**: 장비 사양, VM·노드 사양(Master VM 설계안 8 vCPU · 32GB · 120GB), Worker 수용 용량 산정(신규).
4. **04 네트워크**: 망 정의, 전체 구성도(Bastion에 NTP 추가), 노드별 포트, 클러스터 네트워크 파라미터, 호스트명·IP 할당표, DNS 레코드, Bastion 서비스, NTP 설계·방화벽 요구사항(신규), NMState·NAD, VM 네트워크 매핑.
5. **05 스토리지**: CSI·StorageClass 설계 값, 연결 준비, 동일 EMC 사용 계획, 용량 산정.
6. **06 클러스터 설치**: install-config 주요 값, Master 스케줄 설정, MachineConfig(chrony·multipath), Master KVM 호스트 구성, 설치 순서.
7. **07 MTV**: Provider·Plan 설계, 스토리지 매핑·이관 방식.
8. **08 백업·운영**: etcd·게스트 백업(데이터 에이전트, OS TAR 이관 직후 수동 실행, Windows 전용 툴), 운영 제약.
9. **09 제약·확정 항목**: 설계 제약과 담당별 확정 필요 항목.

## 팀장 검토 의견 반영 (2026-10-13)

1. **구축설계서 분리**: 작업계획서와 별도 문서로 신규 작성.
2. **이관 구성도 개선**: 작업계획서 v2.8의 AS-IS | TO-BE 구성도를 바탕으로, 기존 장비에서 새 역할로 가는 곡선 화살표를 그려 역할별 장비 배정을 한 그림으로 설명(팀장 스케치 반영).
   - 장비 재구성: 자홍색 실선, 안정화 후 Worker2 전환: 주황 점선, MTV 이관(업무 VM → Worker1 VM): 초록 실선. 남색 제목 띠와 구분되도록 재구성 화살표를 자홍색으로 지정.
   - AS-IS 패널은 폭을 줄이고 연회색 제목 띠·작은 글씨로 낮추고, TO-BE 패널을 넓혀 목표 구성을 강조.
   - 패널 제목(AS-IS·TO-BE)은 가로 띠 대신 패널 왼쪽 세로 띠로 표기해, 재구성 화살표가 제목을 가로지르지 않도록 정리.
   - 작업 순서 ①~⑤를 화살표 라벨에 표시. 재활용 TNS-2100은 현재 미사용이라 AS-IS에 그리지 않고, TO-BE의 Bastion·Master 위에 번호와 함께 "+ 추가 장비"로 표시(화살표 수 축소: 외부망 2개, 내부망 3개 + MTV).
   - 구성도에서 네트워크 정보(망 버스·결선·NAD/브리지)는 제외하고 04장 네트워크 설계에서 다룸.
   - MTV 이관 화살표는 장비 아래로 돌려 Worker1 VM으로 진입하도록 배치(위쪽 재구성 화살표와 분리).
   - 그림마다 아래에 작업 카드 ①~⑤를 두고, 카드 번호 색을 그림 번호 색(추가 장비·재구성·MTV·안정화 후 전환)과 맞춤.
   - 처음 만든 현재 → 이관 기간 → 최종 3단계 흐름도는 이 구성도로 대체.
3. **Master 표현**: TO-BE Master 상자 안에 KVM 하이퍼바이저 영역(점선)을 두고, 그 안의 master-0·1·2에 VM 마크를 붙여 KVM 호스트의 VM임을 표시. Bootstrap 임시 VM(설치 후 삭제)도 함께 표기.
4. **HV 1대로 전체 MTV 가능 여부**: 03장 Worker 수용 용량 표로 정리.
   - HV 사양: 태진티엔에스 TR2210 H4, 48코어(24코어 × 2소켓), 1TB(1,048,576MB), 5대 동일.
   - 이관 VM 자원(vCenter·DNS 제외): 외부망 vCPU 108 · 364GB, 내부망 vCPU 196 · 760GB.
   - 판단: 외부망 메모리 약 43%, 내부망 약 82%로 Worker1 1대에 수용 가능. 메모리 예상치는 VM 오버헤드(VM당 약 0.4GB)·노드 예약(약 30GB)·플랫폼 Pod(약 40GB) 가정을 포함하며 Worker1 편입 후 실측해 갱신.
   - DNS VM: 망마다 1대, 4코어 · 8GB, 별도 HV 로컬 디스크. MTV 대상 아님.

## 추가 반영 사항

- **Bastion NTP 연동**: 망별 NTP 서버(망 내부) → Bastion(chronyd) → 노드 구조. 방화벽은 망마다 Bastion → NTP 서버 123/UDP 1건, 1차(10월) 신청. 노드는 chrony MachineConfig로 Bastion을 바라봄.
- **Master 스케줄**: `compute.replicas: 0`으로 설치 시 Master가 스케줄 가능해지므로 Worker1 편입 후 `mastersSchedulable: false`로 변경. Worker1 단독 기간 Ingress replicas 1.
