01. 추진 개요

본 작업은 기존 VMware 환경의 가상머신을 OpenShift로 이관하고, 기존 장비와 재활용 서버를 활용하여 대상 인프라를 구성하는 것을 목적으로 합니다. 망별 HV#01은 VM 집약 및 MTV 이관 원본으로 유지하며, 대상 Worker1을 우선 구축합니다. 이관 완료 후 HV#01을 Worker2로 전환합니다.

목표 구성은 MTV 완료 후를 기준으로 작성했습니다. 이관 기간에는 Worker1을 우선 운영하고, HV#01은 VMware 원본으로 유지합니다. Master는 역할 단위로 표시했으며, 실제 노드 수와 물리·가상 및 HA 구성은 상세 설계에서 확정합니다.

DB 레거시 풀은 재구성 대상에서 제외하며, 본 구성도는 VMware 전환 대상 환경을 표시합니다. 연결선은 논리적 네트워크 구성을 나타냅니다. 물리 회선 수·스위치·Bond 방식 및 VM NIC/NAD/브리지 상세는 미확정입니다. Master·Bastion의 연결망은 추가 설계 후 표시합니다. 동일 EMC 스토리지를 사용하며, 망별 풀·볼륨 할당과 대상 스토리지의 실제 연결 경로는 추가 확인합니다. 관리망은 BMC/OOB를 의미하지 않습니다.

동일 EMC 스토리지 사용 계획 — 이관 기간

CSI는 볼륨 할당·연동 방식입니다. FC 등 실제 데이터 연결 프로토콜은 EMC 모델과 지원 드라이버를 확인한 후 확정합니다. NAS/BK망과 VM 데이터스토어의 FC 경로는 구분합니다. 기존 NFS 언급은 NAS·백업 용도 등 적용 범위를 별도로 확인하며, VM 데이터스토어 방식으로 표기하지 않습니다.

스토리지 용량 산정 초안

동일 EMC에서 기존 VMware 데이터스토어를 유지하면서 MTV 대상 볼륨을 추가 확보합니다. 원본 데이터스토어와 대상 볼륨을 별도로 관리하며, 이관 및 원본 보관 기간에는 두 영역을 동시에 수용해야 합니다. 풀별 잔여 용량과 망별 VM 설정·사용 용량을 확보한 뒤 산정합니다.

사업 관련 동시 확보 공간 = 기존 VMware 데이터스토어 유지분 + MTV 대상 볼륨 + 추가 공간·운영 여유
추가 필요 공간 = MTV 대상 볼륨 + 오버헤드·플랫폼 공간 + 임시·스냅샷 공간 + 운영 여유
부족분 = max(0, 추가 필요 공간 − 사업에 할당 가능한 실제 잔여 용량)

산정식은 초기 검토 기준이며, 실제 필요 용량은 자원 현황 확보 후 확정합니다. 사업에 할당 가능한 실제 잔여 용량은 원본 데이터스토어 유지분을 제외한 값입니다. 원본 유지분은 추가 필요 공간에 중복 가산하지 않으며, 원본 삭제로 회수할 용량도 사전에 가용 공간으로 계산하지 않습니다. 같은 풀을 공유하는 경우 여유 공간을 망별로 중복 계산하지 않습니다.

05. 단계별 수행 계획

단계작업 내용진행 전 확인 / 완료 기준
1. 현황·백업 확보HV·VM·네트워크·FC LUN·데이터스토어 현황 및 설정 기록, 복구 가능한 백업 확보VM별 OS·NIC·디스크·부팅 설정 기록 및 백업, 콘솔 접근, 망별 HV#01 수용 자원 확인
2. VMware VM 집약외부 VM 13식·내부 VM 26식을 각 망 HV#01로 집약VM 이동 방식 확정, 서비스 정상 확인, 나머지 HV의 VM 잔존 여부 확인
3. 장비 재구성외부 HV#02 및 내부 선정 HV를 Worker1으로 구성합니다. 외부 Bastion 장비 출처와 내부 잔여 HV 용도는 확인 후 반영합니다.외부 HV 번호별 배정 확정, IP 중복 방지, 재구성 전 데이터·설정 보존
4. 신규 인프라 구축재활용 서버로 외부 Master, 내부 Master·Bastion 구성Master 실제 구성·설치 방식·호환 버전 및 신규 IP 확정
5. OpenShift 기반 검증클러스터·가상화 기능·네트워크 구성, EMC CSI 드라이버 설치 및 StorageClass·대상 볼륨 할당 검증Worker1 단독 자원 수용 여부, CSI 볼륨·VM 디스크 기능, 동일 EMC 원본·대상 용량과 이관 중 I/O 부하 확인
6. MTV 준비·시험 이관소스·대상 연결 및 망·스토리지 매핑 구성, 주요 OS·다중 NIC·디스크 유형별 시험 이관, 보정 절차와 소요 시간 기록MTV 버전·이관 방식 확정, 연결·권한·인증서·필요 통신 확인, 시험 결과 기록
7. 회차별 본 이관회차별 대상 선정 → 사전 검사 → 이관 및 원본 종료·최종 동기화 → 대상 기동 → NIC·디스크 보정 → 업무 검증동일 서비스 원본·대상의 동시 활성화 방지, 회차별 성공·실패·재작업 기록
8. HV#01 전환 판단대상 서비스 검증, 원본 보관 및 복구 조건 확인원본 HV를 재구성해도 되는 시점 명시, 백업 및 데이터 복구 경로 확보
9. Worker2 추가각 망 HV#01 재구성 → Worker2 편입, 기존 IP 재사용노드·네트워크·CSI 볼륨 접근 정상 확인, VM 배치·이동 검증 범위 협의
10. 완료 기록최종 구성·IP·VM 이관 결과 및 잔여 작업 정리MTV 완료, OS 기동, 디스크·네트워크·업무·백업 정상 확인 및 합의된 검수 항목 충족, 결과서 갱신

3~5단계의 세부 수행 순서는 설치 방식과 Master 구성에 따라 확정합니다. 작업 명령, 수행일 및 소요 시간은 상세 작업 절차서에 반영합니다.

디스크·마운트디스크별 용량·용도, Linux fstab·UUID·LVM, Windows 드라이브 문자를 기록합니다.데이터 디스크 누락, 마운트 및 애플리케이션 경로 변경 여부를 확인합니다.
NIC·IP·라우팅NIC별 이름·MAC·Port Group·VLAN·IP/Prefix, 게이트웨이·DNS·정적 경로·MTU를 기록하고 설정을 백업합니다.NetworkMap과 실제 대상 NIC를 대조합니다. 이름 또는 순서만으로 서비스망·NAS/BK망을 판단하지 않습니다.
암호화·보안 부팅Secure Boot·vTPM·BitLocker·LUKS 사용 여부와 지원 절차를 확인합니다. 복구 키는 승인된 보관 위치에 확보합니다.해당 기능을 사용하는 VM은 적용 버전의 지원 절차를 검증합니다. 보고서에는 비밀 키를 기재하지 않습니다.
게스트 도구·에이전트VMware Tools, QEMU Guest Agent, 보안·백업·모니터링 에이전트 현황을 기록합니다.변환 후 도구 처리 결과와 대상 에이전트 설치·동작을 확인합니다. VMware Tools 사전 제거를 일괄 지시하지 않습니다.
스냅샷·웜 이관 조건기존 스냅샷, CBT 상태 및 필요한 여유 공간을 확인합니다. Windows 웜 이관은 VSS 등 사전 조건을 확인합니다.사전 복사와 최종 변경분 반영이 정상 완료되는지 확인합니다.
라이선스·시간·서비스하드웨어 정보 종속 라이선스, DNS·시간 동기화, 서비스 자동 기동·배치와 외부 연계를 조사합니다.재인증·재등록 필요 여부와 실제 업무 동작을 확인합니다.
Worker1·EMC 수용 능력망별 Worker1 단독 운영 기간의 CPU·메모리와 원본·대상 스토리지 동시 사용량을 확인합니다.이관 복사와 운영 I/O가 겹치는 조건에서 응답시간·디스크 지연을 확인하고 회차·동시 이관 수를 결정합니다.

시험 대상은 주요 OS, 다중 NIC, 다중 디스크 및 보안·암호화 등 특수 구성을 포함하여 선정합니다. 보정 소요 시간과 허용 기준은 시험 결과를 근거로 회차별 작업계획에 반영합니다.

순서수행 내용
1. 사전 기록·백업VM별 NIC 매핑표와 IP·경로 정보를 확보하고 게스트 네트워크 설정을 백업합니다.
2. 이관·전환원본 VM 종료와 최종 데이터 반영 이후 대상 VM을 운영망에서 기동합니다. 동일 IP의 원본·대상이 동시에 활성화되지 않도록 합니다.

5. 검증·판단서비스·NAS/BK망별 통신과 업무를 확인합니다. 보정이 지연되는 경우 합의한 원복 기준에 따라 조치합니다.
